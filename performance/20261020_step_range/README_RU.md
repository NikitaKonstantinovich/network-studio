# Основной шаг, адаптивное дробление и диагностика

Выбранный **«Шаг, мкс»** — максимальный основной шаг, а не обещание одного
вычисления RK4 на этот интервал. Допустимый диапазон определяет общая функция
`integration_step_range(Config)`; её использует GUI, а `validate()` применяет
это же правило при создании Simulator, чтении JSON и checkpoint, запуске CLI.

| Состав сети | Диапазон |
|---|---|
| Все нейроны Ижикевича, астроцитов нет | 1–500 мкс включительно |
| Есть HH либо хотя бы один астроцит | 1–50 мкс включительно |

Наличие астроцита ограничивает шаг и при выключенной обратной связи.
Вид синапса не меняет диапазон. Если после добавления астроцита или переключения
на HH шаг превышает 50 мкс, опыт остаётся невалидным: запуск заблокирован.
Кнопка **«Уменьшить шаг до 50 мкс»** явно применяет исправление со штатным сбросом.
Автоматического изменения шага, интервала записи или шума нет.
Ошибочный черновик остаётся в редакторе, а последнее принятое состояние сети
сохраняется до исправления. Красная плашка поясняет, что графики относятся к
прежнему принятому опыту. Команда «Сброс» отменяет такой черновик и сбрасывает
прежнюю принятую конфигурацию; успешная загрузка JSON/checkpoint заменяет его.
Пока ошибка не исправлена, команды продолжения и изменения протокола отклоняются.

`sample >= dt` и `dt <= noise_interval <= 1 с` остаются обязательными,
включая нулевую амплитуду шума. Например, для `dt=500 мкс` запись через
50 мкс несовместима: отдельно выберите интервал записи 500 мкс или больше либо уменьшите
основной шаг. Чтобы не путать частоту и интервал: **интервал записи должен
быть не меньше dt**, то есть частота записи не выше `1/dt`.
Существующий пресет может требовать этой ручной правки перед увеличением шага.

Параметры работающего расчёта не редактируются. Изменение шага на паузе
сбрасывает опыт по обычным правилам редактора; смена вычислительных потоков
его не меняет. При восстановлении checkpoint переопределение `--dt`
по-прежнему запрещено.

## Что осталось неизменным

`kinetic_step_limit()`, контроль физического состояния, точные линейные переходы,
RK4 с удвоением шага, норма ошибки (`1e-11 + 1e-8·max(|old|,|next|)`,
делитель 15), локализация событий и порядок STDP не изменены. Решатель
продолжает дробить шаг по границам стимулов, шума, записей, доставок и событий.
Укороченный при поиске порога отрезок завершается сбросом/доставками/обучением,
после чего рассчитывается остаток. Пробные вычисления не становятся новым
модельным временем.

Больший разрешённый шаг не означает автоматически больший фактический шаг
и не гарантирует линейного ускорения или одинаковой долгой траектории.
Для событийных и хаотических сетей сравнивайте несколько шагов на своём
протоколе. Если включён нейроанимат, его период и этапы сохраняют существующее
округление вверх к сетке основного шага; для сравнения контроллера выбирайте
интервалы, кратные всем сравниваемым `dt`.

## Статистика расчёта

На основной панели GUI, в выводе CLI и в `_summary.json` показаны:

* `maximum_main_step_s` — заданный `Config.dt`;
* `accepted_internal_steps` — число принятых отрезков с продвижением времени;
* `rejected_attempts` — число отвергнутых попыток по ошибке или физическим границам;
* `accepted_model_time_s` — реально достигнутое модельное время;
* `mean_internal_step_s` — модельное время / число принятых отрезков.

В JSON эти поля сгруппированы в `integration_statistics`. Счётчики записываются
десятичными строками `uint64_t`, без преобразования через double.

**Один принятый отрезок** означает одно зафиксированное продвижение Simulator
к следующему времени, в том числе укороченному до события. Для его состояния
метод использует два полушага RK4; стадии RK4 и два полушага не считаются
отдельными принятыми отрезками. Пробы бисекции порога, неудачные попытки и
само событие без продвижения времени не увеличивают число принятых отрезков.
Ошибочная проба, после которой шаг уменьшается вдвое, увеличивает только
`rejected_attempts`.

Статистика накопительная от начала опыта. Пауза, этапы, заморозка обучения,
изменение числа потоков, запись и восстановление checkpoint её не обнуляют.
Полный сброс или редактирование модели с созданием нового Simulator обнуляет
оба счётчика; среднее до первого продвижения равно нулю.
При вычислительной ошибке показаны уже принятые продвижения и сделанные
отклонённые попытки; продолжение ошибочного состояния по-прежнему запрещено.
Число основных вызовов `step()` остаётся отдельным полем `steps`.

Сумма принятых продвижений равна текущему времени: оно начинается с нуля,
не скачет при смене этапов и восстанавливается точно. Поэтому среднее не
требует дополнительного накопления суммы с округлением. Учёт выполняется
за постоянное время на принятие/отказ, без прохода по нейронам или синапсам.

## Совместимость

Config остаётся **JSON 9**, старые допустимые JSON читаются. Новое состояние
содержит два дополнительных счётчика и использует **NSCP 7**. Идентификатор
численного алгоритма остаётся
`event-rk4-doubling-exact-linear-localized-stimulators-animat-v5`, поскольку
метод не менялся; строгий fingerprint сборки обновлён. **NSCP 1–6 и другие
fingerprint отвергаются**, используйте исходный EXE для старого снимка.
Миграция старых счётчиков по приблизительным оценкам не выполняется.
Новая схема сохраняет точное продолжение и статистику в совместимой сборке.

Архив NSH 2 и workspace 5 не меняются. Исторические отчёты о прежних сборках
сохранены; их контрольные суммы не относятся к новому EXE.

Из `E:/asp/26_27/configurator`:

```powershell
powershell -ExecutionPolicy Bypass -File .\build.ps1 -Test -Smoke

C:/Python313/python.exe -X utf8 performance/20261020_step_range/verify_cli.py `
  --cli build/Release/network_studio_cli.exe `
  --work verification/step_cli_new

C:/Python313/python.exe -X utf8 performance/20261020_step_range/measure.py `
  --config E:/asp/26_27/labs/lab6_config_initial.json `
  --output verification/step_measure_new --threads 8 --repeats 3

C:/Python313/python.exe -X utf8 performance/20261020_step_range/verify_large_resume.py `
  --cli build/Release/network_studio_cli.exe `
  --measured verification/step_measure_new --output verification/step_resume_new

# Необязательно: сравнение с сохранённой исходной сборкой при dt=25 мкс.
C:/Python313/python.exe -X utf8 performance/20261020_step_range/measure_overhead.py `
  --baseline verification/step_range_20261020/baseline/network_studio_cli.exe `
  --current build/Release/network_studio_cli.exe `
  --config verification/step_measure_new/dt_25.json --output verification/step_overhead_new
```

Скрипт измерений читает исходный JSON, проверяет сеть 500/15 041 и делает
отдельные копии с изменённым **только dt**. Исходные seed, параметры, длительность,
интервалы шума/записи и выбор записываемых объектов сохраняются. Каждый процесс
последовательно измеряет окна 0–0,05 и 0,05–0,1 с; время загрузки и экспорта
не входит в `solve_s`. Процессы не запускаются параллельно.
Каждая группа повторов обязана дать побайтово одинаковый конечный checkpoint.

Оценка 1000 модельных секунд вычисляется как
`медиана времени 0,1 с × 1000 / 0,1`. Это ограниченная линейная экстраполяция
раннего участка, **не выполненный опыт на 1000 с**. Она не учитывает изменение
активности, стоимости длинных журналов и последующего анализа/экспорта.
Исходная политика записи может не вместить полную историю 1000 с: её ёмкость
нужно проверять отдельно. Скрипт не меняет её ради ускорения.

Целевые C++-проверки находятся в `step_range_tests.cpp`: диапазоны, интервалы,
короткие импульсы, события/задержки, счётчики, checkpoint и сравнение шести
детерминированных сценариев с шагом 1 мкс. Критерии: одинаковое число/порядок
событий, ошибка времени менее 1 мкс, веса/следы менее `1e-5`, потенциал вдали
от сброса менее 0,01 мВ, максимальная абсолютная ошибка конечных координат
менее 0,002 в их единицах. Это критерии регрессии, не ослабление допусков решателя.
Для графика потенциала исключается окрестность ±10 мкс вокруг спайка эталона,
где сдвиг мгновенного сброса делает обычное сравнение значений некорректным.
