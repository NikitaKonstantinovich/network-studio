# Измерения однопоточного решателя

Актуальная серия на найденной исходной сети ЛР6 (500 / **15 041**, σ=3, seed=42),
побитовые проверки и результаты многопоточных измерений: [20.10.2026](20261020_lab6/REPORT_RU.md).
Ниже сохранена историческая методика 19.10.2026 для другой конфигурации.

Серия 19.10.2026 хранится в `20261019_single_thread/`. Исходный опыт с ровно
15 041 связью однозначно не найден. `fixture.json` получен из сохранённого
`experiments/examples/benchmark.json`: 500 нейронов Ижикевича (400 E / 100 I),
15 013 синапсов TM, 11 961 обучаемых возбуждающих связей, мультипликативная
STDP, σ=5, интервал шума 1 мс, seed=706. Изменены только название, длительность
(0,5 с) и шаг (25 мкс). Исходные лабораторные файлы и результаты не изменяются.
`profile_fixture.json` — отдельный диагностический отрезок первых 50 мс.
Запись траекторий выборочная: 6 нейронов и 4 синапса с интервалом 2 мс,
`record_all=false`. Журналы включают спайки всех нейронов и все доставки;
`numbers.bin` содержит полное конечное состояние и веса/следы всех связей.
Измерительный CLI начинает обычный расчёт с включённым обучением; он не запускает
план этапов автоматически. Сохранённый в конфигурации план из четырёх этапов
в этих измерениях не активируется (аналогично запуску CLI без `--stage`/`--sequence`).

## Сборка и последовательный запуск

Из PowerShell (выберите новый каталог результатов для каждого запуска):

```powershell
& 'E:/asp/26_27/configurator/performance/build.ps1' -Build 'build/performance'
python 'E:/asp/26_27/configurator/performance/run.py' --exe 'E:/asp/26_27/configurator/build/performance/Release/network_studio_benchmark.exe' --fixture 'E:/asp/26_27/configurator/performance/20261019_single_thread/fixture.json' --out 'E:/asp/26_27/configurator/performance/local_repeat' --repeat 3 --reference 'E:/asp/26_27/configurator/performance/20261019_single_thread/before/run_1'
```

`run.py` блокирует одновременный запуск других экземпляров этого сценария.
Не запускайте параллельно сборку, тесты или другой вычислительный эксперимент.
Время `solve_seconds` измеряется после инициализации и до экспорта. В отчёте
сохраняются также время процесса, настройки, SHA-256 и разброс повторов.

Для диагностики соберите отдельный каталог с `-Profile`. Таймеры компилируются
только при `STUDIO_PROFILE=ON`; обычная сборка их не выполняет. Поле
`inclusive_seconds` включает вложенные вызовы, `exclusive_seconds` исключает
их: складывать вложенные inclusive-значения нельзя. Инструментированное время
нельзя использовать как исходное время для расчёта ускорения.

## Проверка чисел

`numbers.bin` записывает double как исходные 8 байт без форматирования:
конечное время и счётчики, все состояния, веса и три следа STDP всех синапсов,
записанные траектории, события, доставки и отложенную очередь. Поля записываются
отдельно, без выравнивающих байт структур. Дополнительно сравниваются все
штатные CSV. Несовпадение останавливает сценарий; величина допуска не задаётся.

Checkpoint сохраняется штатной функцией. Его оболочка содержит сведения о
сборке, поэтому бинарные checkpoint разных сборок не используются вместо
сравнения численных данных. Проверка совместимости остаётся включённой;
старые снимки открывают соответствующей сохранённой сборкой.
`compare_checkpoint.py REFERENCE ACTUAL --out REPORT.json` дополнительно
сравнивает все сериализованные байты, исключив только build ID и зависимую
контрольную сумму. Обе исходные контрольные суммы проверяются. Скрипт не
загружает и не переписывает checkpoint, не разрешает продолжение другой сборкой.
Это также проверяет адаптивный шаг, детекторы порогов и состояние протоколов,
которые не входят в `numbers.bin`. Запускайте его между замерами времени.

## GUI

Добавленный режим `network_studio.exe CONFIG --benchmark DIRECTORY` выполняет
обычный `App::draw → advance` и Win32/DX11. Для него передайте `run.py --gui`.
Окно скрыто; отдельно записываются CPU-время построения интерфейса вместе с
решателем, рендеринг, Present и ожидание при occlusion. Это не измерение видимой
GUI-сессии с реальным VSync. Старый `--smoke` считает сеть до отрисовки и не
подходит для измерения одновременного расчёта и интерфейса.

## Сохранённый эталон

В `original-release/` сохранены исходные EXE, в `baseline-release/` — сборка
с измерительным драйвером и выключенными диагностическими таймерами.
Исходники HEAD сохранены в `original-source.zip`, измерительные дополнения —
в `baseline_instrumentation.zip`. Восстановление в отдельный новый каталог:

```powershell
python 'E:/asp/26_27/configurator/performance/restore_source.py' --variant baseline --out 'E:/asp/26_27/configurator/build/performance_baseline_source'
& 'E:/asp/26_27/configurator/build/performance_baseline_source/performance/build.ps1'
```

`--variant stage1` восстанавливает промежуточный пакет кэшей,
`--variant optimized` — исходники итоговой измеренной версии.
Для полного набора тестов соберите `-Targets all`, затем выполните
`ctest --test-dir build/performance -C Release --output-on-failure --parallel 1`.

Архивы исходников, EXE, checkpoint и крупные численные артефакты остаются локально
и исключены из Git. При переносе серии копируйте весь каталог измерений.
