# Выбор метода интегрирования

Методы задаются полем `Config.integration_method` / JSON `integration_method`:
`adaptive-rk4` (по умолчанию), `rk4`, `euler`. Общая функция
`integration_capabilities()` определяет допустимость метода и диапазон основного
шага. Новые методы доступны только Ижикевичу без астроцитов, 1–500 мкс.
HH, смешанная сеть или любой астроцит требуют adaptive-rk4, 1–50 мкс.
Все границы включены. Неподходящие интервалы записи/шума диагностируются,
а не подстраиваются. GUI предлагает явное исправление метода и шага.

## Численный переход

- Адаптивный RK4 сохраняет прежние операции, норму ошибки и допуски.
  Полный шаг сравнивается с двумя половинными; принимаются два половинных.
- RK4 без оценки ошибки вычисляет четыре стадии одного классического шага.
  Принятое состояние не заменяется результатом двух половинных шагов.
- Эйлер вычисляет весь численный блок из производных одного старого состояния.
  Последовательного обновления связанных нейронов нет.

Независимые линейные координаты сохраняют прежние точные аналитические переходы.
Для RK4 они доступны на каждой стадии; для Эйлера производные нейронов используют
их старые значения, а сами линейные координаты переходят точно на конец интервала.
Поэтому Эйлер имеет первый порядок для связанной задачи, даже при точном распаде.
Не менялись уравнения, double, порядок суммирования токов и правила обучения;
fast-math не включён. Это не реализация протокола NeuroNet.

Внутренний интервал ограничен основной сеткой, прежним `kinetic_step_limit()`,
стимулом, шумом, доставкой, записью и командами. У адаптивного метода дополнительно
действуют предложенный шаг и оценка ошибки. У фиксированных методов предложенный
адаптивный шаг не используется: каждый новый участок начинается с разрешённого
максимума. При нарушении физических границ/конечности шаг пробуют уменьшить
вдвое (не более 64 попыток); затем явная ошибка. Обрезания состояния и скрытой
смены метода нет. Ограничение кинетики не гарантирует заданной точности Эйлера.

## Спайки и события

Для адаптивного режима сохранены прежние кандидаты на пересечение в двух
половинах и поиск корня по двум половинным RK4-переходам.
Для обычного RK4 пересечение локализуется бисекцией функции **одного**
RK4-перехода от исходного состояния до пробного времени. Основной кандидат —
пересечение между концами. Если конец ниже порога, но стадия RK4 указывает
на возможный внутренний подъём, проверяется отдельный RK4-переход до середины.
Это проба поиска события, а не step doubling для оценки ошибки или решения.
Для Эйлера траектория численной координаты линейна на участке:
`h_event = h * (threshold - old) / (trial - old)`; состояние в момент события
пересчитывается одним переходом Эйлера на это время. Пробные состояния
не увеличивают счётчик принятых интервалов.

Независимые нейронные проекции и параллельный поиск используют тот же выбранный
метод и тот же порядок входящих токов. Сначала выбирается самая ранняя группа
порогов с прежним временным допуском; затем Izh-сбросы, доставки и скачки ресурсов,
обновления STDP по прежним следам и добавление новых следов. Запись содержит
состояние после событий. Вход справа от границы применяется на следующем участке.
HH не сбрасывается и доступен только в прежнем адаптивном режиме. Доставки
сохраняют `t_emit + delay`, несколько событий внутри основного шага не схлопываются.
Этапы, нейроанимат и очередь команд используют прежние безопасные границы.

## Статистика и совместимость

`accepted` учитывает каждое фактически принятое продвижение времени, в том числе
укороченное до спайка; среднее равно `model_time / accepted`. `rejected` — сумма
`error_rejected` и `state_reductions`; ограничение кинетики не считается отклонением.
Для RK4/Эйлера `error_rejected` внутри равен 0, но GUI/CLI показывает
«не применяется», экспортирует `error_control=false`, `error_rejections=null`.
Нулевой счётчик не означает измеренную нулевую ошибку.

Сброс создаёт нулевые счётчики. **NSCP 8** сохраняет метод, все прежние поля и
два дополнительных uint64-счётчика. Алгоритм:
`event-selected-flow-exact-linear-localized-stimulators-animat-v6`.
Fingerprint по источникам/компилятору не ослаблен; новое описание метода входит
в него. NSCP 1–7 открываются только своей прежней сборкой. Изменить метод/шаг
через CLI при `--resume` нельзя. После ошибки интегрирования файл остаётся
диагностическим: прежнее правило запрета продолжения ошибочного снимка сохранено.

JSON 10 требует поле метода; JSON 1–9 без него выбирает adaptive-rk4.
Архив NSH 2 не меняет бинарной схемы: метод входит в `config.json` и версии
протокола, защищённые существующими контрольными суммами. Все три метода
сохраняются в метаданных обычного экспорта. Обычная запись Config по-прежнему
сохраняет исходное состояние, а не обученные веса.

## Воспроизведение

Из корня проекта:

```powershell
powershell -ExecutionPolicy Bypass -File .\build.ps1 -Test -Smoke
.\build\Release\network_studio_method_tests.exe verification\my_method_tests
python -X utf8 performance\20261021_methods\verify_cli.py --cli build\Release\network_studio_cli.exe --work verification\my_method_cli
python -X utf8 performance\20261020_step_range\verify_cli.py --cli build\Release\network_studio_cli.exe --baseline verification\integration_methods_20261021\baseline\network_studio_cli.exe --work verification\my_baseline_comparison
python -X utf8 performance\20261021_methods\measure.py short --output verification\my_method_measurements --threads 8
python -X utf8 performance\20261021_methods\measure.py long --output verification\my_method_measurements
# Дополнительный длинный адаптивный контроль на более мелкой сетке:
.\build\Release\network_studio_method_benchmark.exe verification\my_method_measurements\adaptive-rk4_25.json verification\my_method_measurements\long_adaptive-rk4_25_1 8 10
python -X utf8 performance\20261021_methods\measure.py report --output verification\my_method_measurements
python -X utf8 performance\20261021_methods\verify_large_resume.py --cli build\Release\network_studio_cli.exe --measurements verification\my_method_measurements --output verification\my_method_resume
```

Команды `measure.py short` и `long` последовательны: сначала три повтора 0–0,1 с для
adaptive-rk4 при 25/50/100/250/500 мкс и RK4/Эйлера при 50/100/250/500 мкс;
затем один расчёт 0–10 с для каждого метода при 500 мкс. Исходный JSON только
читается. Частоты, шум, STDP, seed, режим записи и состояние нейроанимата
сохраняются в копиях. В исходном `lab6_config_initial.json` поле `animat`
отсутствует: это **выключенный** контроллер, а не измерение активного робота.
Для иного исходника используйте `--config PATH`; скрипт проверяет размер сети
и сохраняет контрольные суммы. Новые каталоги обязательны, прежние не затираются.

`segments.csv` отделяет тихие первые 50 мс, следующий всплеск и последующие
полусекундные участки. `timing.json` отдельно содержит загрузку, расчёт, экспорт
и checkpoint; запрошенные/фактические потоки; накопительные счётчики событий,
включая удалённые из ограниченного журнала. Время полного сохранения включает
его собственный экспорт, но не входит в `solve_s`. `profile.json` помечен
`enabled=false` для обычной сборки; диагностическая сборка с `STUDIO_PROFILE`
измеряется отдельно и не смешивается с основной таблицей скорости.

Проверки точности в `accuracy.csv`: эталон adaptive-rk4, 1 мкс, пять небольших
сценариев. Порог сравнительной пригодности: прежнее число спайков, ошибка
времени <0,1 мс, V <0,1 мВ вне ±2 мс от сбросов **обоих** расчётов,
ошибка весов/следов <0,001. Это критерии отчёта, не новые допуски решателя.
Не прошедшие их крупные шаги Эйлера сохраняются в отчёте. Аналитические задачи
отдельно проверяют первый/четвёртый порядок без другого численного эталона.

Отдельная диагностическая сборка и пример профилирования (после завершения
обычных измерений):

```powershell
powershell -ExecutionPolicy Bypass -File performance\build.ps1 -Build build\my_method_profile -Profile -Targets network_studio_method_benchmark
.\build\my_method_profile\Release\network_studio_method_benchmark.exe verification\my_method_measurements\rk4_500.json verification\my_method_measurements\profile_rk4 8 0.1
```

Повторите последнюю команду для других методов с отдельными новыми каталогами.
Профилированные checkpoint имеют собственный fingerprint; их нельзя смешивать
с обычной Release-сборкой. Научные CSV можно сравнивать непосредственно.
