## Алгоритмические изменения

1. Перед каждым внутренним участком собирается компактный массив синаптических токов: `weight * gain`, индекс активности и получатель. Стадии RK читают этот массив вместо повторных разрозненных обращений к структурам пластичности. Произведение вычисляется с прежней ассоциативностью; порядок вкладов каждого нейрона не меняется. После STDP следующая порция пересоздаёт произведения. Для смешанного conductance-пути сохраняется прежний расчёт. Это расходный буфер, не сохранённый вес спайка.
2. Норма ошибки на x64/SSE2 вычисляется по двум независимым double одновременно. Сохраняются все координаты, проверка конечности, `1e-11 + 1e-8*max(...)`, множитель 15 и точное деление. Редукция — только max неотрицательных величин, не сумма. На остальных платформах остаётся скалярный путь. fast-math/FMA и приблизительное reciprocal не включены.

Уравнения, dt, допуски, локализация событий, очереди, порядок STDP и шум не изменены. Новые буферы пересоздаются после загрузки и не требуют сериализации.

## Совместимость контрольных точек

Схема NSCP остаётся **5**, численный алгоритм — `event-rk4-doubling-exact-linear-localized-stimulators-v4`. Идентификатор сборки меняется из-за контрольных сумм исходников. Строгий загрузчик поэтому **не принимает NSCP прежней сборки в новой**, даже при доказанном совпадении расчётов в контрольных сценариях. Сохранены старые EXE для их собственных совместимых файлов. Профилирующая сборка также имеет отдельный ID.

`compare_checkpoint.py` — только чтение и сравнение: проверяет исходные контрольные суммы и все байты, кроме поля build ID и зависящей от него конечной checksum. Он не переписывает файлы, не создаёт Simulator и не даёт права продолжать несовместимый checkpoint. Перезапуск процесса проверяется отдельно внутри каждой сборки через штатный загрузчик.

## Воспроизведение

Из `E:/asp/26_27/configurator` (нужны MSVC/CMake, Python 3):

```powershell
powershell -ExecutionPolicy Bypass -File .\performance\build.ps1 -Build build/native -Targets network_studio_lab_benchmark
powershell -ExecutionPolicy Bypass -File .\build.ps1 -Test -Smoke
python -X utf8 performance/20261020_lab6/measure.py build/Release/network_studio_lab_benchmark.exe performance/20261020_lab6/measurements/NEW_RUN
```

Последняя команда выполняет 3 повтора 1/2/4/6/8/12/16/Auto на обоих окнах. Порядок режимов циклически меняется; процессы идут строго последовательно. Не запускайте одновременно другие тесты, сборки или эксперименты. Сценарий отказывает при существующем каталоге и блокирует второй экземпляр собственного измерителя.

Отдельный прогон без изменения научной конфигурации:

```powershell
build/Release/network_studio_lab_benchmark.exe ../labs/lab6_config_initial.json performance/20261020_lab6/validation/NEW_DIRECT 8 0 0.1
```

Последние два аргумента — **абсолютные модельные секунды** начала измерения и безопасной остановки. Период до начала измеряется как warmup, не входит в solve_seconds. `.nscp` вместо JSON загружается штатно. Выходной родительский каталог должен существовать.

Варианты дополнительной записи: последний аргумент `rolling` включает память на 10 000 строк; `archive` включает ту же политику и дисковую запись, включая доставки. Численная конфигурация одинакова; отличие политики записи явно отмечается. На коротких проверках число строк меньше лимита. Не сравнивайте байты Config/архивного якоря с режимом исходной политики; сравнивайте научные числа/CSV и анализ.

Диагностический профиль:

```powershell
powershell -ExecutionPolicy Bypass -File performance/build.ps1 -Build build/parallel-profile -Profile -Targets network_studio_lab_benchmark
build/parallel-profile/Release/network_studio_lab_benchmark.exe ../labs/lab6_config_initial.json performance/20261020_lab6/validation/NEW_PROFILE 1 0 0.1
```

Таймеры вложены: для долей используйте **exclusive_seconds**, не сумму inclusive. В параллельном RHS фаза содержит и токи, и нейроны; для отдельного времени нейронов приведён последовательный профиль. Время parallel-фаз — wall на координаторе вокруг барьера, не суммарное CPU помощников. Профилирующие времена нельзя выдавать за ускорение обычного Release.

GUI transport (без рендера) и реальный Win32/DX11:

```powershell
build/Release/network_studio_runner_benchmark.exe ../labs/lab6_config_initial.json performance/20261020_lab6/validation/NEW_RUNNER 10 1 8 0.1
build/Release/network_studio.exe ../labs/lab6_config_initial.json --compute-threads 8 --display-hz 10 --benchmark performance/20261020_lab6/validation/NEW_GUI --benchmark-until 0.1
```

`--benchmark-until` ограничивает RunTo, а не Config.duration. Снимки, GUI/ImPlot, CPU-подготовка DX11, Present и ожидание скрытого окна измеряются раздельно. Это настоящий backend, но скрытое окно; измерение не характеризует видимую анимацию, несколько мониторов или GPU-время. `worker_publish_seconds` измеряет подготовку снимков, `consumer_apply_seconds` — применение данных headless-потребителем; снимки не являются отдельными симуляциями.

Полный опыт можно запускать обычным CLI, **он не выполнен этой короткой проверкой**:

```powershell
build/Release/network_studio_cli.exe --config ../labs/lab6_config_initial.json --threads 8 --output performance/20261020_lab6/validation/NEW_FULL150 --checkpoint performance/20261020_lab6/validation/NEW_FULL150.nscp
```

Для ветвей до 400 с используется отдельно подготовленный пакет эксперимента и реальные времена команд; короткие окна данного отчёта не подтверждают его завершение. Оценки длительности 150–400 с линейной экстраполяцией не учитывают позднюю активность, рост журналов и изменившиеся веса.

Повтор независимой проверки после двух матриц: `python -X utf8 performance/20261020_lab6/validate.py performance/20261020_lab6/validation/NEW_EQ`. Скрипт `overheads.py NEW_DIRECTORY` проверяет запись/GUI; `paired.py` чередует сборки; `profile.ps1` собирает диагностический профиль. Для повторного запуска фиксированных `paired.py`/`profile.ps1` выберите новые имена каталогов, не удаляя старые результаты. `report.py` агрегирует завершённые артефакты исходной серии.

Интерпретатор этой серии: `C:/Python313/python.exe` (в командах `python` можно заменить на этот путь). Диагностическое продолжение дополнительно охватывает 0,1–0,5 с; измерительная серия с записью тоже доходит только до 0,5 с.
