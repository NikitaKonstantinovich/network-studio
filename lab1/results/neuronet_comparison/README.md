# Контрольное сравнение с NeuroNet SM R05

В оригинальном NeuroNet пользователь проверил один RS-нейрон при одинаковой стимуляции **10 Гц, амплитуда 30, длительность 3 мс**. При `Step=0.500` в показанном 100-мс кадре виден один полный спайк и последующий подпороговый подъём примерно до −55 мВ. После изменения шага на `0.025` видны два полных спайка. Таким образом, двойной ответ при малом шаге наблюдается и в исходной программе.

Это объясняет расхождение с одиночным ответом оригинала при крупном шаге для данного контрольного опыта. Оно не доказывает, какие шаги использовались для исторических рисунков лабораторной, и не переносит проверку автоматически на 2 или 20 Гц.

## Что именно зафиксировано

Параметры на двух предоставленных пользователем скриншотах: `a=0.02`, `b=0.2`, `c=-65`, `d=8`, `Spike showing=1`; глобальный `Noise=0`, индивидуальный шум выключен. Один стимулятор подключён к нейрону ID 1. `Frame duration=100`, таблица `(50,0), (53,30), (100,0)`. Оба графика `Em` показывают кадр длиной 100 мс.

| Исходная программа | Видимых полных спайков на импульс в кадре | Показание `Frequency` |
|---|---:|---:|
| [Step 0.500 мс](nn_step_0p5.png) | 1 | 20 |
| [Step 0.025 мс](nn_step_0p025.png) | 2 | 40 |

Сырые времена событий исходной программы **не экспортировались**. Картинки подтверждают форму ответа в показанном кадре; средние частоты по многосекундному журналу из них не измерялись. Начальное состояние и история ручной сессии не восстановлены.

`Frequency` — оконный счётчик, а не средняя частота за весь опыт. В проверенном бинарном файле окно по умолчанию равно **50 мс**, а формула — `1000 × число событий в окне / длина окна в мс`. Поэтому одно событие даёт 20, два — 40. При одиночном ответе каждые 100 мс этот индикатор может чередовать 0 и 20, хотя долговременная частота составляет 10 Гц.

## Что установлено чтением бинарного файла

Проверен `neuronet_3_SM.exe`, PE32/x86, размер 1 193 472 байта, SHA-256:

```text
997fe22f54185a4bba16903d9d4d357c0d3d6589678579580e715cdddea2c333
```

Встроенная строка версии: `NeuroNet SM R05 based on Neuronet Ver. 3.0R24. Added the ability to connect a virtual robot. By Sergey Lobov and Alexey Zharinov 2009-2022`. Исходники этой версии в найденной установке отсутствовали; бинарный файл здесь не распространяется. Адреса, поля и выбранные инструкции сохранены в [binary_evidence.json](binary_evidence.json) и [binary_evidence.asm](binary_evidence.asm).

Функция нейрона `0x445d90` выполняет один явный шаг Эйлера, используя старые `V,u` в обеих производных:

```text
dV = 0.04*V*V + 5*V + 140 - u + I
du = a*(b*V - u)
V += dt*dV
u += dt*du
if V >= 30:
    V = c
    u += d
    Is_spike = true
    V_old_plot = 30
обновить таймер и затем обработать выход/регистрацию события
```

Сброс проверяется **после** интегрирования. `Spike showing` соответствует полю, записываемому в `.net` как `refractory_time`; оно ограничивает регистрацию событий/выхода таймером. Производные `V,u` продолжают вычисляться каждый шаг. Удержания `V=30` или пропуска интегрирования на 1 мс здесь нет. При положительном `Spike showing=1` в рассматриваемых переводных расчётах все пересечения порога зарегистрированы ровно по одному разу.

Стимулятор обновляется перед нейроном. Его фаза округляется вниз до десятых долей миллисекунды; выбирается первая строка с `Frame time >= phase`. Для указанной таблицы ток равен 30 при `50 < phase <= 53`. При шаге 0.5 мс это шесть отсчётов: 50.5, 51, 51.5, 52, 52.5, 53 — полные 3 мс, а не случайно укороченный импульс. Дополнительного коэффициента усиления между выходом стимулятора и током нейрона в этой ветви не обнаружено.

## Воспроизводимый численный контроль

Из каталога `standalone/network_studio` после сборки CLI:

```powershell
python .\lab1\neuronet_probe.py
# Другой каталог сборки:
python .\lab1\neuronet_probe.py --cli .\build\network_studio_cli.exe
```

[neuronet_probe.py](../../neuronet_probe.py) использует только стандартную библиотеку Python и настоящий `network_studio_cli`. Оригинальный NeuroNet этот скрипт не запускает. Он рассчитывает ровно два перевода Эйлера и один запуск RK4, без дополнительных обзоров параметров.

Во всех трёх расчётах выбраны `V(0)=-70`, `u(0)=0`, длительность 3 с; анализируется поздний интервал `[1,3)` с. Это заданное начальное состояние численного опыта, а не восстановление состояния пользовательской сессии. Сравнивается периодическая последовательность стимулов; результат не следует смешивать с ответом на единственный импульс после полного покоя.

| Источник численных событий | Шаг, мс | Событий на `[1,3)` с | Средняя частота по этому журналу | События в последнем периоде, мс |
|---|---:|---:|---:|---|
| Python-перевод найденного алгоритма Эйлера | 0.5 | 20 | 10 Гц | 2952.5 |
| Python-перевод найденного алгоритма Эйлера | 0.025 | 40 | 20 Гц | 2951.750; 2953.675 |
| Исполнение `network_studio_cli`, RK4 | 0.025 | 40 | 20 Гц | 2951.650; 2953.500 |

Здесь числа 10/20 Гц вычислены из численных журналов; они отличаются по смыслу от показаний оконного индикатора 20/40 на скриншотах. Перевод Эйлера воспроизводит наблюдаемую смену одиночного ответа двойным. RK4 при малом шаге даёт тот же тип ответа, что и оригинальная программа при `Step=0.025`.

Крупный шаг влияет на момент первого пересечения порога и сброса. В установившейся серии остаточная переменная восстановления `u` также отличается от состояния покоя. При Euler 0.5 мс первый сброс наступает позже, поэтому после него остаётся меньше времени под током; после выключения стимула напряжение возвращается к покою. При малом шаге после сброса остаётся достаточно возбуждения для второго спайка. Поэтому ответ на первый изолированный импульс нельзя использовать как замену проверке поздних периодов. Отдельный [аудит одиночного импульса](../audit_numerics/README.md) проверяет уравнения, дозу стимула и сходимость к двум независимым адаптивным решателям.

Совпадение отдельных времён не заявляется: перевод использует Python binary64, тогда как исходный x87 может сохранять расширенную точность промежуточных величин. Кроме того, NeuroNet использует квантованную фазу с включённой правой границей, CLI — обычный прямоугольный импульс `[50,53)` мс. Перевод записывает время начала шага, а CLI — его конца. Эти отличия явно сохранены в метаданных.

- [probe_results.json](probe_results.json) — переводные времена и сводка реального CLI, хеши скрипта, конфигурации и CLI.
- [probe_stdout.txt](probe_stdout.txt) — краткий вывод запуска.
- [rk4_10hz_30x3.json](rk4_10hz_30x3.json) — конфигурация, открываемая в конфигураторе.
- [rk4_10hz_30x3_events.csv](rk4_10hz_30x3_events.csv), [trace.csv](rk4_10hz_30x3_trace.csv), [summary.json](rk4_10hz_30x3_summary.json) — подлинный экспорт CLI; время в CSV дано в секундах.
