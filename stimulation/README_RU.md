# Общие источники и поле активности

Постоянные функции Network Studio, доступные для поддерживаемых сетей HH/Ижикевича. Сборка CPU/Win32/DX11, без CUDA. Примеры находятся в `stimulation/examples/`. Научная конфигурация JSON имеет схему 7; конфигурации схем 1–6 продолжают читаться. При отсутствии источников прежний вход и порядок вычислений сохранены.

## Управление

1. Нажмите **«Стимуляторы…» → «Добавить стимулятор»**. В списке выберите источник; укажите получателей, амплитуду, частоту, начало/окончание, ширину и задержку первого импульса. Таблица внутри периода использует тот же механизм, что индивидуальные входы.
2. **«Применить без сброса»** регистрирует команду на безопасной границе текущего расчёта; статус показывает фактическое модельное время. Изменение не вызывает `App::edit()`. Для явного нового поезда есть **«Применить с новой фазой»**. Черновик до применения не влияет на динамику. Пока вычислитель подтверждает команду, элементы управления источниками недоступны. После подтверждения редактор получает фактически принятые параметры, включая нормализованное начало и задержку. Над ним отдельно показаны **действующие параметры**, принятые **ожидающие параметры** с временем применения, последняя применённая команда и следующий импульс. Ошибка команды сохраняет черновик для исправления, но не изменяет действующие параметры.
3. **«Пространственная область»** заменяет явный список получателей кругом с центром X,Y, радиусом и фильтром E/I/все. Числа используют `Config.space`: при пространстве 100×100 `um` радиус 40 означает 40 мкм. В условном пространстве единицы остаются условными. Нет скрытого пересчёта и ослабления амплитуды с расстоянием.
4. На схеме оранжевый квадрат — центр источника. Один щелчок выбирает его, перетаскивание перемещает, двойной щелчок открывает инспектор. Получатели выделяются кольцами. Можно двигать источник во время работы; фактические координаты применяются между завершёнными шагами. При разном масштабе осей физический круг выглядит эллипсом.
5. В инспекторе нейрона перечислены общие источники и их текущие вклады. Прежний индивидуальный вход остаётся отдельным: при добавлении общего он автоматически не выключается. Команды автоматического переноса протокола нет.
6. **«Этапы эксперимента…»** позволяют выбрать общие источники по ID. При входе в этап выбранные источники получают новые параметры поезда, старый импульс обрывается, фаза начинается от момента входа + задержки этапа. Пустая группа источников сохраняет их протоколы. Очередь явных команд остаётся действующей.
7. В **«Сеть / стимуляция» → «Параметры анализа…»** выберите общий опорный источник. Шесть получателей одного импульса не превращаются в шесть стимулов анализа. Доступны отметки на графике и журнал начал/окончаний. Отдельные окна анализа имеют независимый выбор источника.

## Сигнал и время

Для нейрона: `I = I_DC + I_individual + sum(I_shared) + I_noise`. Для сохранения численной совместимости вычислительный порядок прежней части остаётся `(DC + индивидуальный импульс) + шум`, затем добавляется сумма общих источников в порядке возрастающих стабильных ID. При пустом списке нет дополнительного сложения с нулём. HH использует мкА/см²; Ижикевич — единицы тока модели. Одинаковые амплитуды у этих моделей не являются калибровкой физически одинакового воздействия.

Начало фазы источника — `signal.start + first_delay`, глобальное окончание — `signal.stop`. Интервалы полуоткрытые `[start, stop)`. Частота 0, выключенный источник и нулевая амплитуда не подают импульсы. Таблица содержит интервалы внутри периода. Соприкасающиеся интервалы без нулевого промежутка образуют один непрерывный импульс журнала; ширина не меньше периода также даёт непрерывное воздействие до stop.

Интегратор разделяет внутренние шаги по всем границам этих сигналов и временам команд, наряду со старыми границами шума, записи, доставок. Частота кадров не задаёт фазу сигнала. Детерминированный шум не потребляет дополнительные случайные числа. Макрошаг, частота записи, локализация порогов, точные линейные переходы и правила STDP сохранены.

Перемещение/изменение радиуса или получателей посреди импульса меняет вход сразу после фактического момента применения: текущий сигнал направляется текущим получателям, ID активного импульса и фаза сохраняются. Движение нейрона обновляет пространственный состав и создаёт версию протокола.

Для смены частоты действуют следующие правила (все времена абсолютные, в секундах):

- **До первого запланированного импульса**, без новой фазы: команда применяется в запрошенное время, но `signal.start` и `first_delay` сохраняются. Для таблицы учитывается также начало её первого интервала. Пример: при start=150, first_delay=0,05 смена 10 → 1 Гц в t=150 оставляет первый импульс в t=150,05.
- **Во время действующего поезда**, без новой фазы: частота меняется на ближайшей границе старого периода, не предшествующей запросу. Текущий импульс и остаток периода завершаются по старым параметрам. На границе принятый `start` равен времени применения, `first_delay=0`. Если раньше наступает старый stop, применяется эта граница окончания. Таблица продолжает задавать смещения от нового начала периода.
- **Точно на границе** используется она; один представимый double после границы относится уже к следующему периоду. Сравниваются абсолютные границы, без допуска, склеивающего разные времена.
- **«С новой фазой»**: команда применяется в запрошенное время; `signal.start` заменяется фактическим временем применения, введённый `first_delay` сохраняется. Введённое абсолютное начало не используется. Активный импульс закрывается, новый начинается после задержки (плюс смещение первого табличного интервала). Состояние нейронов, ресурсы и обучение не сбрасываются.
- **Одновременная смена частоты и start/first_delay без новой фазы отклоняется целиком** с пояснением. Для неё используйте «С новой фазой». Изменение только начала/задержки без изменения частоты сохраняет прежнюю семантику явного абсолютного расписания: применяется сразу, может изменить или прервать текущий сигнал. Поле stop всегда абсолютное и должно оставаться допустимым после нормализации.
- Выключение (`enabled=false` или частота 0) применяется сразу и закрывает текущий импульс. Повторное включение без новой фазы использует сохранённую абсолютную сетку; если включить внутри её импульса, подаётся только оставшаяся часть с новым ID журнала. Для новой отсрочки от включения выберите новую фазу. После stop частота сама по себе не запускает источник заново: требуется продление stop и подходящее расписание.

При смене частоты вместе с амплитудой, шириной, положением или получателями **вся команда** применяется в выбранный момент — эти параметры не разделяются на независимые команды. Прогноз следующего импульса учитывает текущую конфигурацию и уже принятую очередь `(time, sequence)`, включая включение/выключение и группы одновременных команд. Он не предсказывает будущие изменения этапов, внешние команды и правки черновика. Непрерывное ненулевое воздействие не показывается как серия новых импульсов; выключенный, завершённый и не подающий импульсов источник имеют отдельные статусы. Импульс за пределами текущей длительности помечается явно.

Команда — полный снимок параметров источника. Несколько ожидающих команд выполняются по `(time, sequence)`, последняя в один момент задаёт итоговые параметры. Последующая полная команда может заменить ранее запланированное положение или частоту: контроллер должен учитывать очередь.

Проверка смены частоты сравнивает поля с действующим источником в момент постановки команды; уже ожидающая команда не становится действующим протоколом раньше срока. Для нового редактирования действующей версии используйте «Перечитать параметры». Отдельной операции изменения/отмены одной ожидающей команды пока нет. `SimulationRunner` возвращает нормализованный снимок в `RunnerResult::accepted_stimulator`, а время — в `applied_time`; GUI принимает их только после соответствующего `snapshot_sequence`. Сам черновик не является источником истины для действующего сигнала.

Порядок на временной границе: интегрировать старый участок → локализованные пороги/сбросы, доставки, ресурсные скачки и STDP по прежнему соглашению одновременных следов → запись отсчёта. На конце макрошага затем выполняется переход этапа, затем команды источников. Во внутренних границах выполняются команды, затем начинается следующий участок с правосторонним входом. Новые параметры не меняют события уже завершённого участка. Позиционные команды сами не создают спайки/доставки.

Каждый ненулевой непрерывный импульс получает `(stimulator_id,pulse_id)` один раз на весь источник. В `_shared_stimuli.csv` записаны начало, завершение, амплитуда и получатели **при начале**, этап. У незавершённой записи `complete=0`, end — достигнутое время. Изменения посреди импульса доступны в `_stimulator_commands.json` и `_protocols.json`; последнее содержит полные версии, включая состав после перемещения нейрона и входа в этап. Исторический график входа использует соответствующую версию, не текущую область. ID источника после удаления не переиспользуется; удаление нейрона со сбросом корректирует индексы получателей.

## Поля весов и активности

В панели топологии включите **«Поле активности»**. Синее поле весов и оранжевое поле активности можно показать совместно. В **«Настройки активности…»** задаются критерий, окно W в секундах, интервал ответа, тип/модель связей и отдельный масштаб стрелок. Обычные связи можно скрыть. Настройки сохраняются в рабочем пространстве схемы 4 отдельно от Config/checkpoint; рабочие пространства 1–3 читаются с выключенным новым полем.

Два критерия:

- **Доставки по связям:** хотя бы одна фактическая доставка в `(t-W,t]`. Время генерации в растровом графике не подменяется временем доставки.
- **Доставки с последующим ответом:** доставка в том же окне и спайк её приёмника до текущего времени, с `response_min <= t_post - t_arrival <= response_max` и строго `t_post > t_arrival`. Одновременные доставка и спайк исключаются даже при response_min=0. Каждая доставка помечается подходящей только один раз; один постспайк может удовлетворить несколько доставок разных или одной связи. Повторные постспайки её не умножают. При уходе доставки из окна её вклад исчезает, даже если ответ ещё внутри окна.

Второй критерий — операционное временное совпадение, **не доказанная причинность**. Постспайк мог возникнуть от внешнего источника, шума или суммы входов. Для тормозных связей он не измеряет подавление; используйте фильтр и интерпретируйте отдельно.

Для каждой ячейки `V = sum(|w_ij(t)| * e_ij)` по активным связям, пересекающим ячейку. Связь учитывается один раз, независимо от числа доставок/ответов. Их число показано отдельно в подсказке. Используется текущий обученный вес, как и в токовой модели; никакого замораживания веса при генерации нет. Доступен текущий модельный момент и пауза, исторической перемотки поля нет: конечные веса не выдаются за исторические.

Геометрия общая с полем весов: направления и сетка в нормализованной плоскости `[0,1]²`, X вправо, Y вниз; экранный масштаб/DPI в численный вектор не входят. Для прямоугольного физического пространства направление нормализованного вектора не следует трактовать как физическую скорость. Граничные ячейки полуоткрыты, внешняя граница включена; пересечения нулевой длины, самосвязи и совпадающие координаты не добавляются. Отключённая связь не даёт вклада. Отрицательный вес не переворачивает геометрическое направление. Единицы весов разных моделей не приравниваются. Правила обхода ячеек и компенсации сумм общие с существующим полем весов.

## Контроллер, CLI и воспроизведение

Вне выполняющегося `Simulator::step()`:

```cpp
Stimulator value = sim.config.stimulators.at(0);
value.x = 40; value.y = 50;                 // Config.space units
const double actual = sim.schedule_stimulator(value, requested_time, false);
// Or sim.move_stimulator(id, x, y, requested_time).
// ID=0 creates a new source and reserves a monotonic ID.
```

`requested_time` и результат — **абсолютные секунды модельного времени**. Прошлое, неконечные значения, неизвестные ID и превышение бюджета отклоняются. API не является потокобезопасным: внешний контроллер передаёт команды через очередь главного вычислительного потока на завершённой границе шага. Будущие команды разделяют интегрирование в точное время и не округляются к dt. `replay_stimulators(vector<StimulatorCommand>)` принимает уже зарегистрированные точные времена/параметры и уникальные номера sequence, не выполняя повторного преобразования фазы. Это API будущего нейроанимата; арена, сенсоры, динамика робота не реализованы.

Численная выборка поля без GUI:

```cpp
TopologyViewState view;
view.activity_window = .05;
view.activity_mode = 1;
view.response_min = .001; view.response_max = .02;
WeightField geometry;
ActivityField activity;
// Reuse both caches between iterations, after completed sim.step().
geometry.update(sim.config, &sim.plasticity, view);
activity.update(sim, view, geometry);
if (activity.available) {
    WeightCell vector = activity.vector_at(sim.config, x_model, y_model);
    // vector.x/y, vector.count, vector.events; no GUI context needed.
}
```

Запрос вне пространства возвращает нулевую ячейку. Недоступное окно вызывает явную ошибку, а не достоверный ноль. После замены Simulator создайте новый ActivityField. Его кэш производный, не является вторым расчётом сети.

```powershell
.\build\Release\network_studio.exe --config .\stimulation\examples\shared.json
.\build\Release\network_studio.exe --config .\stimulation\examples\spatial.json
.\build\Release\network_studio_cli.exe --config .\stimulation\examples\spatial.json --stimulus-commands .\stimulation\examples\moves.json --stop-at 0.0075 --checkpoint .\build\moving.nscp --output .\build\moving_part
.\build\Release\network_studio_cli.exe --resume .\build\moving.nscp --checkpoint .\build\moving_end.nscp --output .\build\moving_end
```

`--stimulus-commands` читает зарегистрированные changes и ожидающие commands из документа типа `network-studio-stimulator-commands`, schema=1. Для повторения используйте **исходную** конфигурацию опыта; изменения этапов и положения нейронов повторяются отдельно тем же планом/API. Удаление источника записывает выключение: воспроизведение команд воспроизводит прекращение сигнала, оставляя выключенный объект. Для точного восстановления всей структуры используйте checkpoint. Нельзя повторно загружать уже выполненные команды в resumed-процесс; они уже сохранены. Отсутствующие будущие параметры не восстанавливаются из кадров/координат мыши.

## Форматы, память и ограничения

Config schema=7: `stimulators[]`, `next_stimulator_id`, `activity_horizon`. Идентификаторы uint64 записаны десятичными строками. `signal` содержит `start,stop,frequency,amplitude,width,pulse_intervals`; `first_delay` отдельно. Список источников отсортирован по ID; recipients — уникальные нулевые индексы нейронов. Числа double в JSON используют достаточную точность round-trip; checkpoint хранит численные массивы двоично. Область использует `spatial,x,y,radius,filter` (0=все,1=E,2=I). До 64 источников, 64 интервалов в таблице, 4096 команд/изменений и 4096 версий протоколов; превышение даёт ошибку, не молчаливую потерю.

Checkpoint schema=4, алгоритм `event-rk4-doubling-exact-linear-localized-stimulators-v4` плюс строгий fingerprint сборки. Помимо прежней динамики/ресурсов/следов/порогов/доставок/истории сохраняются источники, счётчики ID, активные pulse-latches, журнал импульсов, очередь и история команд, снимки версий, ограниченное окно активности и счётчики его начала. После загрузки рабочие буферы входов пересоздаются, а ActivityField пересчитывается из окна; нет повторной подачи активного импульса. Старые checkpoint открываются только исходной совместимой сборкой; Config 1–6 мигрирует отдельно.

Исправление смены частоты от 20.10.2026 **меняет fingerprint сборки**, сохраняя схему checkpoint 4 и JSON 7. Старые checkpoint нельзя продолжить новой сборкой; используйте исходную. В пределах новой сборки отложенная команда и принятые параметры восстанавливаются точно. Уже записанный журнал команд содержит нормализованные значения: replay выполняет их буквально и не исправляет прежнее ошибочное время первого импульса задним числом. [Регрессии и результаты новой проверки](frequency_20261020/REPORT_RU.md).

`activity_horizon` задаётся в Config **до запуска**: по умолчанию 1 с, допустимо .001–10 с. Расчёт хранит отдельно от отображаемой History до 250000 доставок и 250000 нейронных спайков, удаляя старые записи. После превышения лимита поле показывает предупреждение, пока запрашиваемое окно не станет полностью доступным. Память окна не растёт с общей длительностью. На кадре разбираются новые события; геометрия кэшируется, суммирование использует текущие веса. Пауза не потребляет события повторно. Список получателей пространственного источника проверяется линейно по нейронам: при текущем пределе 1000 узлов отдельный пространственный индекс не нужен; приведены измерения для 500/15000.

Журнал импульсов подчиняется существующему `bounded_journals`/`journal_capacity`. В ограниченном режиме удаляются старые завершённые записи, активные сохраняются; `_summary.json` сообщает границу доступной истории. При полном журнале без ограниченного режима расчёт останавливается с диагностикой. Потенциалы имеют прежний отдельный лимит. Протоколы и управляющие команды не сокращаются, поэтому длинный опыт с более чем 4096 изменениями управления требует будущего расширения потокового протокольного журнала; текущая версия явно отклоняет превышение. Автоматический экспорт на диск каждый кадр не включён.

Примеры: `shared.json` — шесть получателей, один источник; `spatial.json` + `moves.json` — круг 40 мкм с перемещением посреди импульса; `chain.json` — задержанная цепь, последний канал с нулевым токовым gain показывает доставку без гарантии ответа; `fields_1hz.json` и `fields_10hz.json` — тот же граф и веса при разных частотах. В этих примерах параметры не подбирались под требование обязательного постспайка. Совпадение с NeuroNet и биологическая достоверность не утверждаются.

Для совместного просмотра цепочки с критерием ответа откройте `chain.json` и загрузите `activity_response.nsworkspace` через «Рабочее пространство…». Либо:

```powershell
.\build\Release\network_studio.exe --config .\stimulation\examples\chain.json --workspace .\stimulation\examples\activity_response.nsworkspace
```
