# Checkpoint Network Studio: формат 1

Это снимок одного `Simulator`, сделанный синхронно между вызовами `step()`. API не является потокобезопасным: вызывающая сторона должна остановить вычисление до чтения/сохранения объекта. GUI выполняет расчёт и файловые операции в одном потоке и разрешает сохранение на паузе. CLI останавливается после завершённого `step()`, не вставляя дополнительных границ в интегрирование.

## Представление

Все целые поля — unsigned 64-bit little-endian, включая длины и boolean (строго 0/1). Double — 8 байт IEEE-754 binary64 little-endian, через копирование битов, без численного преобразования в целое. Строка — длина в байтах и байты UTF-8; массив — число элементов и элементы. Структуры C++, указатели и функции не записываются.

Порядок полей:

1. 26 байт ASCII `NETWORK-STUDIO-CHECKPOINT\n`; uint64 версии (1).
2. Строки идентификатора алгоритма `event-rk4-doubling-exact-linear-localized-v1` и SHA-256 отпечатка численной сборки. Отпечаток учитывает исходники модели/интегратора/кодеков, compiler ID/version, платформу, разрядность и флаги CMake.
3. Config JSON схемы 4 с 17 значащими цифрами и массив всех `Config.parameters` как binary64. Общие параметры обоих представлений должны совпадать. Исходные веса остаются в Config.
4. `time` (double), `steps`, `next_sample`, `suggested_step` (double), `checkpoint_boundary`, `done`, строка `error`.
5. Массив `state` полной размерности `4*N + 4*S + 7*A`; массив plasticity, по четыре double на связь: `weight`, `pre_trace`, `post_trace`, `post_slow_trace`.
6. Массивы uint64 `spikes`, `releases`; массив boolean `thresholds.armed` (сначала N нейронов, затем A астроцитов).
7. История: массив времени; таблица столбцов состояний; таблица столбцов весов; массив событий (`time` double, индекс uint64, флаг astro). Не выбранные для записи столбцы пусты, однако текущее состояние соответствующих объектов сохранено полностью.
8. FNV-1a-64 от всех предыдущих байтов, uint64 little-endian. Это контроль случайного повреждения, не криптографическая аутентификация.

Размер файла проверяется до чтения: максимум 256 МиБ. Config — максимум 64 МиБ; диагностика — 64 КиБ. До выделения каждой таблицы проверяются число элементов, оставшиеся байты, размер графа, максимум 100001 отсчёта, 16 млн записанных значений и 2 млн событий. Проверяются конечность, физические границы, ресурс TM, диапазоны весов/следов, строгий порядок отсчётов, время событий/индексы и точное соответствие журналов счётчикам. Допускаются сохранённые вне сетки конечные отсчёты от ранее завершённых и затем продлённых расчётов.

## Восстановление и эквивалентность

Загрузка сначала строит отдельный новый Simulator из Config, затем заменяет все сохранённые поля и проверяет инварианты. Начальный отсчёт конструктора заменяется сохранённой историей целиком; он не дописывается к ней. GUI заменяет текущий объект только после успешной загрузки и оставляет его на паузе.

Производные `outgoing`, выбор столбцов истории, координаты/значения порогов и рабочие векторы `Flow` строятся заново. `armed` загружается из файла даже для значений чуть ниже порога в пределах допуска: вычислять его только по V/Ca нельзя. Callback-функции привязываются к восстановленному `this` в начале следующего `step()`. `held_input_time` заново назначается перед каждым непрерывным участком, до любого пробного RK-шага. Отдельного состояния RNG нет: шум определяется Config.seed, индексом нейрона и временным bin.

Адаптивная последовательность зависит от `suggested_step`, поэтому он сохранён. Главная сетка зависит от `steps`, запись — от `next_sample`; все три поля восстанавливаются без округления. Локализованная группа событий, сбросы Ижикевича, STP/TM, STDP и отсчёты полностью обрабатываются до успешного возврата из `step()`. Само сохранение не вызывает step/record и не расходует случайные числа. В тестах сравнивается весь checkpoint и полный экспорт побайтово, без допуска для чисел.

`done` проверяется по времени/ошибке. Успешно завершённый эксперимент остаётся завершённым; для продолжения нужно явно увеличить Config.duration через `extend_duration()`. История не очищается. Увеличение не равнозначно выбору более позднего конца до начала расчёта: старый конец мог изменить разбиение последнего шага. «Сброс» создаёт новый Simulator из исходной Config и очищает обучение/историю.

Ошибка внутри шага может оставить последний принятый внутренний участок, а не основную границу. Такой файл помечен диагностикой и, при необходимости, `checkpoint_boundary=false`; `step()` и продление запрещены. Даже файл с ошибкой проходит структурные проверки. Невалидная Config, нечисловое состояние либо разрушенная структура не сохраняются.

## Совместимость и надёжность

Гарантия точного продолжения относится к той же сборке и вычислительному окружению (включая реализацию математических функций и режим floating point). Несовпадающая схема, алгоритм или отпечаток численного ядра отклоняются. Автоматической миграции или режима «игнорировать совместимость» нет. Штатный checkpoint не распространяется на отдельный агрегированный `network_studio_population`.

Запись идёт в соседний временный файл; после закрытия потока выполняется замена (`MoveFileExW` с REPLACE_EXISTING/WRITE_THROUGH на Windows, rename на других платформах). При ошибке временный файл убирается, предыдущий остаётся. Это атомарная замена на поддерживающей её файловой системе, а не универсальная гарантия сохранности при потере питания или сбое сетевого хранилища.

При выборе максимальной истории загрузка/сохранение требуют дополнительной памяти для содержимого файла и восстановления объекта. Все операции синхронные; во время сохранения большой истории интерфейс может кратковременно не отвечать. Для полной переносимости эксперимента сохраняйте checkpoint вместе с соответствующей сборкой приложения.
