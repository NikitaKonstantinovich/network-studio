# Поставка Windows x64

Пользовательские инструкции: [установка](../docs/INSTALL_RU.md), [работа с программой](../docs/USER_GUIDE_RU.md).

Сборка и проверка из корня репозитория:

```powershell
powershell -ExecutionPolicy Bypass -File .\build.ps1 -Test -Smoke
```

После проверки закоммитьте исходники и документацию. Затем создайте переносимую поставку:

```powershell
powershell -ExecutionPolicy Bypass -File .\release\package.ps1 -Tag v2026.11.03
```

Скрипт требует чистых отслеживаемых исходников и готовых GUI, CLI и `population` в `build/Release`. Он создаёт новый каталог `build/packages`, ZIP, внешний `BUILD_INFO.json` и `SHA256SUMS.txt`. Повторное использование существующего каталога поставки запрещено; для повторной упаковки задайте новый `-Output PATH`.

В ZIP попадают только программы, примеры, инструкции, материалы примера нейроанимата и метаданные. Лабораторные данные, пользовательские checkpoint, результаты, тестовые EXE и кэши не включаются. `BUILD_INFO.json` содержит точный исходный коммит, численный отпечаток из CLI и SHA-256 программ. Внутренний `CHECKSUMS.sha256` покрывает все файлы поставки, кроме себя; внешний `SHA256SUMS.txt` покрывает ZIP и внешний манифест.

Перед публикацией распакуйте ZIP в новый каталог, проверьте все внутренние хэши, запустите извлечённый CLI, продолжение checkpoint в новом процессе и реальный GUI. Проверьте совпадение EXE с `build/Release` и коммита манифеста с целевым коммитом тега. Публикуйте три внешних файла как вложения GitHub Release, привязанного к этому коммиту; EXE и ZIP не добавляются в историю Git.
