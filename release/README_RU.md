# Поставка Windows x64

Пользовательские инструкции: [установка](../docs/INSTALL_RU.md), [работа с программой](../docs/USER_GUIDE_RU.md).

Сборка и проверка из корня репозитория:

```powershell
powershell -ExecutionPolicy Bypass -File .\build.ps1 -Test -Smoke
```

После проверки закоммитьте исходники и документацию. Затем создайте переносимую поставку:

```powershell
powershell -ExecutionPolicy Bypass -File .\release\package.ps1 -Tag v2026.11.21
```

Скрипт требует чистых отслеживаемых исходников и готовых GUI, CLI и `population` в `build/Release`. Если сборка выполнена с `build.ps1 -ReleaseOutput PATH`, передайте тот же каталог через `package.ps1 -ReleaseDirectory PATH`. В ZIP программы в обоих случаях появятся в `build/Release`, где их ищет `launch.cmd`.

По умолчанию ZIP, внешний `BUILD_INFO.json` и `SHA256SUMS.txt` сохраняются в `build/packages`. Для каждого выпуска задавайте свежий каталог `-Output PATH`, чтобы сохранить сопроводительные файлы предыдущих выпусков.

В ZIP попадают только программы, примеры, инструкции, материалы примера нейроанимата и метаданные. Лабораторные данные, пользовательские checkpoint, результаты, тестовые EXE и кэши не включаются. `BUILD_INFO.json` содержит точный исходный коммит, численный отпечаток из CLI и SHA-256 программ. Внутренний `CHECKSUMS.sha256` покрывает все файлы поставки, кроме себя; внешний `SHA256SUMS.txt` покрывает ZIP и внешний манифест.

Перед публикацией распакуйте ZIP в новый каталог, проверьте все внутренние хэши, запустите извлечённый CLI, продолжение checkpoint в новом процессе и реальный GUI. Сверьте извлечённые EXE с исходным каталогом сборки и убедитесь, что коммит в манифесте совпадает с коммитом тега. ZIP, `BUILD_INFO.json` и `SHA256SUMS.txt` публикуются как вложения GitHub Release.
