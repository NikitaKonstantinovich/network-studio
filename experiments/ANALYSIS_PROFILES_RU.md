# Профили и интервалы сетевого анализа

## Управление

Во встроенной вкладке **«Сеть / стимуляция»** и в каждом отдельном сетевом окне:

1. Настройте **«Параметры анализа…»**: популяцию, частотные окна, пороги гистерезиса, минимальное число/долю участников, объединение пачек, опорный источник и окно ответа.
2. В **«Профили…»** введите имя и нажмите **«Создать из текущих настроек»**. **«Загрузить профиль»** переносит сохранённые параметры в текущее окно. Редактирование окна не меняет сохранённый профиль: подпись получает отметку **«изменён»**. Повторное имя отклоняется; для другого набора создайте новое имя. Максимум 64 профиля, имя до 128 байт UTF-8.
3. Задайте **«От, с» — «До, с»** в абсолютном модельном времени. Для фиксированного конца отключите **«До текущего времени»**. По умолчанию запрос — от 0 до текущего времени. Поля задают статистику; масштабирование, панорама и «Следить за временем» меняют только видимую область.
4. **«Применить профиль и интервал ко всем окнам»** явно копирует текущие параметры и интервал во встроенное и все открытые сетевые окна. Другие виды графиков не меняются. Это также работает для ещё не именованных настроек. Новое сетевое окно наследует настройки встроенного; дубликат — своего исходного окна.
5. Сохраните **«Рабочее пространство…»**. В нём находятся библиотека профилей, настройки и интервал каждого окна, название применённого профиля. Это отдельные данные представления. JSON эксперимента по-прежнему содержит единственные `Config.analysis` как исходные настройки встроенного анализатора; профили не создают ещё одну модель полей `AnalysisSettings`. Профиль оборачивает существующую структуру. Настройки встроенного анализатора передаются контроллеру прежним способом без сброса динамики.

Выбранные нейроны задаются индексами, опорный общий источник — устойчивым ID. При переносе профиля в другую сеть проверьте смысл группы. Несуществующие индексы или источник дают ошибку; несовместимую привязку отдельного окна нужно подтвердить прежней командой перепривязки. Сам профиль не устанавливает соответствие нейронов разных экспериментов.

## Покрытие и границы

Статистический интервал **`[from,to)`**: левый конец включён, правый исключён. Интерфейс отдельно показывает запрос, доступную историю и фактическое пересечение. Будущий конец либо усечённое начало дают заметку **«НЕПОЛНЫЙ интервал»**; пустое пересечение — сообщение об отсутствии данных. Нельзя сравнить такой результат как полный. При паузе параметры пересчитываются сразу; во время работы действует прежнее ограничение обновления на 0,1 модельной секунды. Запрошенные поля относятся к показанному обработанному снимку.

Для выбранной популяции используются все сохранённые спайки до правого конца, в том числе **до `from`**. Детектор не перезапускается на границе запроса. Сохраняются прежние окно `(t-W,t]`, удаление истёкших спайков перед поступившими, пороги, объединение и фильтры участников.

Если журнал сохранён от нуля, начальное состояние детектора известно. Если его начало усечено, одной предыстории длиной `W` недостаточно: гистерезис может тянуться дольше, а соседние кандидаты объединяться. Консервативный критерий определённости — наблюдаемый промежуток без спайков выбранной популяции длительностью **не меньше `W + min_gap`**. До конца первого такого промежутка состояние детектора считается неизвестным. Если промежутка до `from` нет, вывод помечается как анализ с недостаточной предысторией; сравнение полного интервала отклоняется. Пачки до момента определённости не считаются подтверждёнными ответами.

Принадлежность пачки интервалу определяется **началом окончательно объединённого кандидата**. Пачка, начавшаяся до `from`, исключается целиком, даже если продолжается внутри интервала. Начало точно в `from` включается; точно в `to` исключается. Пачка у правого края сохраняется в таблице с `complete=false`, если не завершилась либо не хватает контекста для исключения последующего объединения. Подтверждение требует `end + min_gap + W <= to`. Дополнительное `W` учитывает, что новый кандидат может начать своё время задним числом от первого спайка активного окна. Данные после `to` не используются для подтверждения: результат для одного интервала не меняется при продлении опыта.

В интерфейсе различаются **обнаруженные** и **подтверждённые** пачки. Итоговая `burst_hz` и ответы используют подтверждённые пачки. График скользящей частоты начал, как прежде, включает обнаруженные начала, в том числе неподтверждённые; это явно указано в легенде. Бины частоты спайков привязаны к модельному нулю и обрезаются интервалом; делитель — фактическая длительность бина. Максимум 200 000 бинов; для чрезмерно большого абсолютного времени, неразличимого на заданной сетке double, возвращается ошибка.

Стимулы отбираются по фактическому началу в `[from,to)`. Для общего источника один импульс считается один раз независимо от числа получателей. Окно ответа **закрытое**: `[t_stim + response_min, t_stim + response_max]`. Оно должно целиком лежать в доступном статистическом интервале и в области определённости детектора. Поэтому верхняя граница должна быть **строго меньше `to`**: сам `to` исключён. Неполные окна исключаются из знаменателя доли ответов и из числа пропусков, учитываются отдельно. Каждому допустимому стимулу назначается первая ещё не использованная подтверждённая пачка в окне; одна пачка не используется дважды. Частота стимулов считает все начала, включая стимулы с неполным окном ответа.

## Архивная история

Для полного опыта при ограниченных журналах заранее включите [потоковый архив](../disk_history/README_RU.md). Команда `--analyze-archive` и окно «История на диске…» используют тот же детектор/профиль с чтением предыстории порциями. `--analyze-export` остаётся импортом прежнего CSV с его собственным покрытием и ограничениями.

## Экспорт и сравнение

**«Экспорт анализа расчёта…»** передаёт профиль и интервал вычислителю и читает полные ещё доступные журналы на безопасной границе команды. Экранный снимок ограничен 100 000 событиями на канал; журнал вычислителя может быть глубже. Поэтому одинаковый профиль сам по себе **не гарантирует одинаковое покрытие** экранного и полного экспорта. В `_analysis.json` записаны точные запрошенный/доступный/фактический интервалы, определённость предыстории, полный профиль и показатели. При одинаковых данных, параметрах и интервале окно и экспорт совпадают. Сохранение не достраивает удалённую историю.

Выходные файлы: `_activity.csv`, `_bursts.csv`, `_responses.csv`, `_analysis.txt` и новый `_analysis.json`. У JSON явные `document_type`, `schema_version=1`, `algorithm=trailing-hysteresis-context-v2`; вложенный `profile` — самодостаточный документ `network_studio_analysis_profile`, версия 1, имя и существующие поля `AnalysisSettings`. Double записываются с 17 значащими цифрами; ID источника — десятичная строка. При ручном редактировании окна экспорт содержит **фактические**, а не исходные настройки именованного профиля. Имя — метка, не доказательство равенства.

Меню **«Профили… → Проверить перед сравнением с окном»** проверяет параметры и интервалы двух открытых представлений. Для двух файлов:

```powershell
.\build\Release\network_studio_cli.exe --compare-analysis first_analysis.json second_analysis.json
```

Код 0 — одинаковые параметры, запрошенный и фактический интервалы, полное покрытие, достаточная предыстория и одинаковый размер популяции; 2 — несопоставимость с причиной; 1 — повреждённый/несовместимый документ. Порядок выбранных индексов и название профиля не влияют на равенство. Проверка не утверждает равенства самих чисел и не проверяет научную эквивалентность двух сетей.

## Пример: существующие ветви ЛР6, 280–400 с

Офлайн-режим читает существующие `_experiment.json`, `_summary.json`, `_events.csv` и `_shared_stimuli.csv` (или `_stimuli.csv` для индивидуального опорного входа). Он не запускает модель и не читает несовместимый checkpoint. Сохраните вложенный объект `profile` из `_analysis.json` в отдельный JSON или используйте [готовый общий профиль](analysis_profiles_20261020/lab6_profile.json).

```powershell
.\build\Release\network_studio_cli.exe --analyze-export E:/asp/26_27/labs/lab6_1Hz --analysis-profile experiments/analysis_profiles_20261020/lab6_profile.json --analysis-from 280 --analysis-to 400 --output verification/my_analysis/branch1
.\build\Release\network_studio_cli.exe --analyze-export E:/asp/26_27/labs/lab6_10Hz --analysis-profile experiments/analysis_profiles_20261020/lab6_profile.json --analysis-from 280 --analysis-to 400 --output verification/my_analysis/branch10
.\build\Release\network_studio_cli.exe --compare-analysis verification/my_analysis/branch1_analysis.json verification/my_analysis/branch10_analysis.json
```

Создайте выходной каталог заранее. Готовый сценарий создаёт новый каталог, пересчитывает обе ветви, проверяет показатели по прежнему общему интервалу, частично доступный запрос 250–400 с, сравнение и SHA-256 неизменных лабораторных входов:

```powershell
python experiments/analysis_profiles_20261020/verify_labs.py
```

Пределы импорта: 64 МиБ для конфигурации, 16 МиБ для summary, 256 МиБ / 2 млн строк для каждого CSV, 64 КиБ для профиля. Это чтение штатного экспорта, а не универсальный CSV-конвертер: повреждённые заголовки, числа, индексы и порядок событий отклоняются.

## Совместимость

Workspace **5**, чтение версий 1–4 сохранено. В старых файлах нет библиотеки профилей; интервал получает значение 0 — текущее время. Повреждённый файл не меняет текущее пространство; запись атомарная. На этапе профилей использовались научный JSON **7** и checkpoint **4**. Текущий архивный этап использует JSON **8** и checkpoint **5**; [описание совместимости и переноса архивов](../disk_history/README_RU.md). Алгоритм интегратора не изменён. Но существующий строгий fingerprint включает `analysis.*` и `io.cpp`; поэтому **старые checkpoint несовместимы с этой сборкой**. Проверка не ослаблена. Для продолжения старого состояния используйте исходную сборку; для статистики — её CSV/JSON. Новые checkpoint сохраняются и восстанавливаются обычным способом. Профили/интервалы принадлежат workspace и не добавляются в checkpoint.
