# Пространственная генерация, показатели и этапы

Это собственная модель Network Studio. «Радиус 2» в приведённом примере означает **2 model_unit в прямоугольнике 10×10 model_unit**. Соответствие радиусу NeuroNet, микрометрам, физической скорости проведения и соглашениям его обучения не установлено. Размещение не меняет явно заданные задержки синапсов.

## Генератор

Откройте **«Создать сеть…» → «Связи и расчёт» → «Связи в пределах радиуса»**. Координаты редактора `px,py ∈ [0,1]` переводятся в координаты модели как `X=width*px`, `Y=height*py`. Единицы — явная строка (`model_unit`, `mm`, `um` и т. п.); изменение подписи не выполняет конверсию чисел. Старые JSON получают пространство 1×1 `model_unit`. Панорама, zoom, DPI и размеры окна на расстояния не влияют.

Границы пространства открытые, без периодического заворачивания. Для каждого приёмника выбираются источники с евклидовым расстоянием **≤ radius**. Целевое число входов округляется из заданного нормального распределения и ограничивается количеством допустимых узлов. Кандидаты перемешиваются по seed и выбираются без повторений. Если соседей меньше, используются все доступные; счётчик таких приёмников показан в предпросмотре. Дальних связей для заполнения дефицита нет. Самосвязи по умолчанию запрещены, отдельно разрешаются (режим кольца сохраняет прежнее правило).

Распределения параметров нейронов и весов, E/I-полярность и STDP сохраняют прежние правила генератора. Ближайшие соседи теперь также используют указанные размеры пространства; при прежнем 1×1 результат прежний. Добавление группы требует тех же размеров и единиц, что у существующей сети. Группа остаётся изолированной от старых узлов.

Предпросмотр показывает фактическое число связей, дефицит соседей, средние/SD/диапазоны входов, длин и весов, seed и пространство. **«Распределения образца…»** показывает гистограммы. JSON хранит готовые узлы и связи и отдельные записи происхождения `generation`: настройки распределений, модель/параметры связей, пространство, радиус и seed. Загрузка ничего не генерирует заново. Перемещение/удаление узлов не повторяет генерацию; метаданные описывают исходную операцию создания.

## Сетевой анализ

Именованные профили, явный интервал `[от,до)`, подтверждение предыстории и правила границ описаны в [актуальной инструкции](ANALYSIS_PROFILES_RU.md). Интервал статистики не зависит от видимой области графика. Workspace 5 сохраняет профили и интервалы; `_analysis.json` позволяет проверить их совпадение при сравнении. Число обнаруженных пачек и число подтверждённых для ответов показываются отдельно.

Вкладка **«Сеть / стимуляция»**, а также **«Новый график» → «Сеть / стимуляция»**. Отдельные окна поддерживают прежние docking, перенос на другой монитор, pan/zoom, собственные параметры и экспорт. Анализ читает журнал спайков всех выбранных нейронов, независимо от записи V/u. Настройка анализатора не вызывает сброс и не выполняет шагов симуляции.

Популяции: все, E, I или явная группа. Неперекрывающиеся окна частоты привязаны к модельному нулю: `[k*bin,(k+1)*bin)`. На границе доступного интервала окно обрезается, делитель — **его действительная длительность**. Спайк на правой границе принадлежит следующему окну; спайк точно в конечный момент появится при продолжении наблюдения. Групповая частота — число спайков/с, средняя — число спайков/(N×с). Это разные оси графика.

Детектор использует скользящее окно `(t-W,t]` и частоту всей группы. Из окна сначала удаляются истёкшие события, затем добавляется группа новых событий с тем же временем. При достижении верхнего порога начинается кандидат пачки; начало отмечается первым спайком в активном окне. При достижении нижнего порога кандидат завершается. Кандидаты с промежутком меньше `min_gap` объединяются, затем применяются минимальные число и доля **различных** участников. Экспорт содержит начало, конец, длительность, число спайков, участников и признак завершения. Незавершённая пачка и пачка с неполным левым контекстом после усечения журнала не используются как подтверждённые ответы.

Частота пачек в момент `t` — число начал пачек в `[max(available_from,t-W_b),t)`, делённое на доступную длительность этого окна. Это отдельная оценка, не частота отдельных нейронов.

Журнал стимулов содержит **фактически начавшиеся ненулевые импульсы**, нейрон-получатель, амплитуду и версию протокола. Смежные интервалы одинаковой амплитуды без выключения считаются непрерывным импульсом. DC и шум не считаются поездом импульсной стимуляции. Для синхронной группы выберите одного опорного получателя: шесть получателей одного импульса дают один опорный момент, а не шесть стимулов.

Стимулы обходятся по времени. Каждому назначается первая ещё не использованная **завершённая** пачка с началом в `[t_stim+response_min,t_stim+response_max]`. Пачку нельзя использовать повторно. Неполное правое окно ответа исключается из числа пропусков и показывается отдельно. Показаны доля/число ответов, пропуски, лишние пачки, частоты и гистограмма задержек. Совпадение средних частот само по себе не объявляется синхронизацией.

Пересчёт во время выполнения ограничен интервалом 0,1 с **модельного времени**; на экране указано время обработанных данных. При изменении настроек и завершении расчёта пересчёт выполняется сразу. Максимум 200 000 окон частоты: при превышении нужно увеличить окно анализа, без изменения симуляции. Сопоставление ответов линейно по числу стимулов и пачек.

Общий экспорт CSV использует параметры встроенного сетевого графика и стандартный запрос 0 — текущее время. Для выбранного фиксированного интервала используйте **«Экспорт анализа расчёта…»** в сетевом окне: команда передаёт его настройки и интервал вычислителю, где журнал может быть глубже экранного снимка. В `_analysis.json` записывается фактическое покрытие. Файлы: `_activity.csv`, `_bursts.csv`, `_responses.csv`, `_analysis.txt`, `_analysis.json`, `_stimuli.csv`, `_protocols.json`. В последнем сохраняются все версии входных протоколов. Спайки остаются в `_events.csv`, приходы — в `_deliveries.csv`.

## Этапы и сохранение

**«Этапы эксперимента…»** в верхней панели открывает план, управление обучением, политику журналов и журнал переходов. Изменение плана само по себе не меняет текущую динамику. На паузе доступны **«Войти в этап (пауза)»** и **«Выполнить отсюда до конца»**. Длительность этапа относительная; его конец округляется вверх до обычной временной сетки dt, фактическое время записывается в журнал. Автоматическое выполнение останавливается после последнего этапа.

Для [нейроанимата](../neuroanimat/README_RU.md) используется этот же план.
У этапа доступны смена среды (зоны и параметры связанного источника), сохранение
положения, возврат в начало либо заданные X/Y, а также снимки всех состояний,
весов и следов на входе и выходе. Снимки включаются в checkpoint и
`_animat_stage_states.csv`; отдельные файлы checkpoint автоматически не создаются.
План нейроанимата фиксируется после первого шага: его редактирование требует
сброса. Изменение среды и вход в уже заданный этап выполняются отдельными
командами без сброса сети.

Переход происходит после полностью завершённого `Simulator::step()`: пороги, сбросы, доставки, скачки ресурсов, STDP и отсчёты этой границы уже обработаны по прежнему протоколу. Затем применяются действия нового этапа. Потенциалы, ресурсы, астроциты, веса, очередь, адаптивный шаг, пороги, счётчики, абсолютное время и история сохраняются. Генерация шума остаётся счётчиковой: seed/нейрон/абсолютный временной интервал; переход не сдвигает поток.

Общий флаг обучения блокирует **только изменение весов**; индивидуальные STDP-флаги сохраняют своё значение. При заморозке следы продолжают затухать и получать события. Общий коэффициент умножает суммарное приращение до прежнего ограничения веса; индивидуальное отношение LTP/LTD сохраняется. Очистка следов — отдельное явное действие, записываемое в журнал; веса не обнуляются.

Пустая группа этапа не меняет стимулы. Для выбранных получателей задаётся новый прямоугольный поезд: старый текущий импульс обрывается в момент перехода; первый новый начинается в `t_transition + first_pulse`, остальные отсчитываются от него. Stop равен концу этапа, интервалы полуоткрытые. Таблица выбранных получателей заменяется этим поездом. DC, параметры нейронов и шум сохраняются. Прошлый вход восстанавливается по исторической версии протокола; новые настройки не применяются к прошлым отсчётам. Ровно на границе используется правая, новая версия входа.

Это правило перезапуска поезда относится к обычной группе стимулов этапа.
Связанный источник нейроанимата управляется его средой и не должен одновременно
выбираться в этой группе. Для него при смене частоты сохраняется фаза:
первый запланированный импульс либо завершение текущего периода. Автоматическая
смена этапа предшествует тику контроллера на той же границе; пользовательские
действия выполняются после тика. Полный порядок приведён в инструкции нейроанимата.

Checkpoint сохраняет план, настройки встроенного анализатора, активный этап, автоматическое выполнение, общие параметры обучения, версии протоколов, журналы стимулов, глубину журналов и счётчики удалённых записей вместе с прежним полным состоянием. После открытия GUI остаётся на паузе. **«Независимое продолжение из состояния…»** загружает снимок и добавляет запись происхождения; абсолютный шумовой/событийный clock и прошлые данные сохраняются. Последующие результаты принадлежат новой ветви опыта. Это не сброс времени к нулю.

**«Экспорт весов как начальной конфигурации…»** создаёт отдельный JSON с текущими весами как начальными. Он начинает новый опыт с начальными состояниями нейронов/ресурсов. Обычное сохранение JSON по-прежнему не подменяет исходные веса обученными. Обычный **«Сброс»** отбрасывает динамику и восстанавливает начальные состояния текущей конфигурации, включая исходные веса; для продолжения пользуйтесь этапами/checkpoint.

## Длинные опыты и память

По умолчанию потенциалы/ресурсы ограничены прежними 1 млн отсчётов и 32 млн скаляров; бюджет проверяется до старта/продления. Для полного длинного опыта доступна [запись на диск с ограниченным окном ОЗУ](../disk_history/README_RU.md). Увеличение интервала этой записи не прореживает журнал спайков: локализация событий остаётся прежней.

Для длинных опытов включите **«Ограниченные журналы»** заранее (в лабораторных примерах уже включено). Каждый журнал событий, доставок и стимулов ограничен `journal_capacity` (50 000…2 000 000 записей). При заполнении удаляется старая половина с сохранением целых временных групп. Счётчики всех спайков/выбросов и удалённых доставок продолжают расти. Очередь будущих доставок — отдельная структура, из неё ничего не удаляется для экономии истории; её прежний предел 1 млн остаётся явной ошибкой модели/нагрузки.

Без включённой записи на диск это режим ограниченной **доступной истории**. Удалённые события невозможно восстановить из одного checkpoint. Анализ показывает общий доступный интервал спайков и стимулов; экспорт и сводка указывают его начало. Старые потенциальные траектории могут оставаться длиннее журнала событий. Для полного опыта заранее включите «История на диске…»; анализ произвольного интервала и ветви checkpoint описаны в [инструкции архива](../disk_history/README_RU.md). Переключение уже усечённого журнала обратно в «полный» запрещено.

Полные журналы старых JSON сохраняют прежнюю семантику и предел 2 млн; предупреждение видно до запуска. Переполнение полного журнала останавливает расчёт с диагностикой, не выдавая частичный снимок за возобновляемое состояние. Включение ограниченной истории не меняет физическую траекторию.

## Ручное выполнение сценария ЛР6

1. Откройте `experiments/examples/lab6_1hz.json`: 400 E + 100 I, входы 30±3, |w|=0,5±0,1, радиус 2 в 10×10 model_unit, seed 706. Предпросмотр может дать небольшой дефицит входов у границ. Параметры нейронов, TM, шума и мультипликативной STDP явно сохранены в файле; они не объявляются восстановленными параметрами NeuroNet.
2. В окне этапов войдите в **Background** и запустите. По завершении сохраните общий checkpoint.
3. Войдите в **Training**, выберите шесть получателей N1–N6, частоту 1 Гц, длительность 100 с. После расчёта сохраните checkpoint и экспорт; зафиксируйте параметры детектора.
4. Откройте **тот же общий checkpoint** и выполните такой же этап при 10 Гц. Не начинайте вторую ветвь из результата первой. Не меняйте детектор для получения ожидаемого ответа.
5. Для чистого сравнения тестовой стимуляции после обучения сохраните один обученный checkpoint и выполните обе частоты из него с выключенным обучением. Для продолжения одной ветви используйте **Frozen test** (200 с), затем **Retraining** (100 с).
6. Сравните временное сопоставление, задержки, долю ответов, пропуски и лишние пачки, а не только средние частоты. Сохраните результаты и при отсутствии синхронизации. Откройте независимые окна активности, растра, веса и векторное поле для наблюдения обучения.

Для пакетного выполнения есть `experiments/run_lab6.ps1`; он сохраняет общий снимок и две ветви. Полный прогон на этой CPU-сборке может занимать много часов; наличие файлов с длительностью 100/200 с само по себе не является свидетельством выполненного длинного опыта. Фактически завершённые интервалы и измерения приведены отдельно в отчёте.

```powershell
# Полная последовательность из JSON; индекс этапа нулевой.
.\build\Release\network_studio_cli.exe --config experiments/examples/stages.json --sequence 0 --checkpoint result.nscp --output result
# Независимое продолжение из общего состояния с планом другой частоты:
.\build\Release\network_studio_cli.exe --resume common.nscp --plan experiments/examples/lab6_10hz.json --stage 1 --checkpoint result10.nscp --output result10
# --run-for задаёт относительную длительность, --stop-at / --until — абсолютное время.
# Заморозка и скорость обучения на безопасной границе:
.\build\Release\network_studio_cli.exe --resume result.nscp --continue-current yes --until 1 --learning frozen --learning-rate 1 --output frozen
powershell -ExecutionPolicy Bypass -File .\experiments\run_lab6.ps1
```

Текущий JSON схемы **9** читает схемы 1–8; workspace **5** читает версии 1–4. Checkpoint **7** имеет строгий идентификатор сборки и не обещает продолжение старых бинарных снимков несовместимым решателем. Для них сохраните исходную сборку. Рабочее пространство хранит настройки независимых анализаторов отдельно от модели; checkpoint хранит настройки встроенного анализатора и состояние нейроанимата. [FORMAT_RU.md](FORMAT_RU.md) описывает исторические схемы JSON 6 / checkpoint 3; текущие дополнения — в инструкциях [дисковой истории](../disk_history/README_RU.md) и [нейроанимата](../neuroanimat/README_RU.md).
