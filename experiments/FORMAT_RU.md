# Форматы пространственных экспериментов

## Config JSON 6

Сохраняет прежние поля и готовые массивы графа. Схемы 1–5 читаются; новые поля при отсутствии получают значения по умолчанию. Числа double выводятся с 17 значащими цифрами.

| Поле | Значение |
|---|---|
| `space` | `{width,height,unit}`; по умолчанию 1×1 `model_unit`; `X=px*width`, `Y=py*height` |
| `generation` | Массив `{settings_json,first,count}`; протокол исходных операций создания, а не команда повторной генерации |
| `analysis` | Популяция, группа, окна частот/пачек, пороги, участие, промежуток, опорный нейрон и окно ответа |
| `stages` | Массив именованных этапов с относительной длительностью, обучением, коэффициентом, очисткой следов и настройками импульсов группы |
| `bounded_journals` | По умолчанию false; true разрешает удаление старой половины каждого заполненного журнала |
| `journal_capacity` | 50 000…2 000 000 записей на журнал; по умолчанию 2 000 000 |

Индексы групп/опорного нейрона нулевые. Все времена JSON — секунды. `AnalysisPopulation`: 0 — все, 1 — E, 2 — I, 3 — группа. `NetworkTopology` в метаданных: прежние 0–3, 4 — радиус. `settings_json` — строка самостоятельного JSON версии 1 с seed, пространством, радиусом, политикой самосвязей, распределениями и шаблоном синапса. Метаданные сохраняются как происхождение даже после ручного изменения графа.

Этап содержит `name`, `duration`, `learning`, `learning_rate`, `clear_traces`, `neurons`, `stimulus_enabled`, `amplitude`, `frequency`, `width`, `first_pulse`. План не является текущим состоянием выполнения. Обычный JSON сохраняет исходные веса; отдельный экспорт обученных весов создаёт новый JSON с заменёнными начальными весами.

## Checkpoint 3

Алгоритм: `event-rk4-doubling-exact-linear-localized-stages-v3`. Помимо алгоритма требуется точное совпадение отпечатка исходников численного ядра и компилятора. Гарантия точного продолжения ограничена той же совместимой сборкой и вычислительным окружением. Версии 1–2 отклоняются, их открывают сохранённой прежней сборкой.

Сохраняется префикс полезной нагрузки [версии 2](../delays/FORMAT_RU.md), но версия заголовка равна 3. После исполненных и ожидающих доставок, перед итоговой контрольной суммой, добавлены последовательно:

1. `dropped_spikes`, `dropped_releases`, `dropped_deliveries` — три массива: длина uint64 и значения uint64 по узлам/связям.
2. `events_after`, `deliveries_after`, `stimuli_after` — три binary64, время последней удалённой группы.
3. Число стимулов uint64 и записи: `time` binary64, `amplitude` binary64, `neuron` uint64, `protocol` uint64.
4. UTF-8 JSON состояния выполнения: длина uint64 и байты. Поля `learning`, `learning_rate`, `automatic`, `stage_active`, `stage_end`, `stage_index`, `origin`, `protocols`.

Каждая версия протокола содержит `time`, `end`, `name`, `learning`, `cleared`, `learning_rate` и входные параметры каждого нейрона: DC, амплитуду, частоту, начало/конец, ширину, таблицу импульсов и индивидуальный шум. `end` закрытой версии равен времени следующей записи. У последней версии `end==time` означает открытый конец; фактический правый предел наблюдения — время Simulator. Несколько действий в один момент допустимы; действует последняя версия этого времени.

Все двоичные целые и binary64 имеют little-endian порядок. Float/counter не проходят через преобразование uint64→double. Ограничения: файл 512 МиБ, JSON выполнения 128 МиБ, до 4096 переходов, до 256 этапов, штатные лимиты графа, записанных состояний и очереди. Проверяется контрольная сумма FNV-1a, длины, индексы, конечность, временной порядок, связи событий с протоколами, счётчики с учётом удалённых записей. Это контроль повреждения, не криптографическая аутентификация.

Снимок создаётся только вне вызова `step()`. Неудачный расчёт остаётся диагностическим и не возобновляется. Запись использует прежний атомарный механизм через соседний временный файл. Загрузка сначала полностью разбирает новый Simulator. Рабочие буферы, adjacency и callbacks пересоздаются; сериализуются веса, все следы, пороги, адаптивный шаг, очередь, время/счётчики и история. Шум по-прежнему определяется seed, нейроном и абсолютным временным интервалом.

## Рабочее пространство 3

Отдельный `.nsworkspace`, лимит 4 МиБ. Сохраняется раскладка версии 2, затем JSON настроек встроенного анализатора, число независимых окон и JSON настроек каждого окна в том же порядке. Тип `PlotKind::Network` имеет значение 7. В конце остаётся контрольная сумма. Версии 1–2 читаются с анализатором по умолчанию. Численные результаты не записываются в workspace.

## Экспорт

Дополнены прежние файлы:

- `_stimuli.csv`: фактически начавшиеся импульсы по получателям;
- `_protocols.json`: состояние выполнения и версии протоколов;
- `_activity.csv`: время, спайки/с группы, спайки/(нейрон·с), пачки/с;
- `_bursts.csv`: начало, конец, длительность, спайки, участники, завершённость;
- `_responses.csv`: стимул, ответ, задержка; `-1` означает отсутствие подтверждённого ответа;
- `_analysis.txt`: параметры анализа, доступный интервал, количества и частоты;
- `_summary.json`: дополнительно глубина каждого журнала.

Экспорт нескольких файлов не является единой атомарной транзакцией: каждый файл заменяется атомарно отдельно. Для нового опыта используйте новый префикс. Ограниченный журнал не восстанавливает удалённые данные и не заменяет полный потоковый архив.
