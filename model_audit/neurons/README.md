# Независимая проверка нейронных моделей

Проверены текущая Release CLI и связанная с ней существующая `network_core.lib`, без изменения или пересборки production. SHA256 CLI: `4965bb5cc41f13f243bf9823f9c3d6c68c1ab0a77d1677574007003f50342a8e`. Ошибок в правых частях нейронных уравнений, знаках токов и переводе времени не обнаружено. Это проверка реализации выбранных моделей, не подтверждение биологической точности всей сети.

## Уравнения и первичные источники

В [Izhikevich, 2003, с.1569, уравнения (1)–(3)](https://www.izhikevich.org/publications/spikes.pdf):

```text
dv/dt_ms = 0.04 v² + 5v + 140 − u + I
du/dt_ms = a(bv − u)
при v ≥ 30: v ← c, u ← u+d
```

В программе обе производные умножены на 1000 (`network.cpp:289–295`); время хранится в секундах. `I` — единицы модели, не автоматически мкА/см². Начальное `u=bV` соответствует опубликованному примеру; пользователь может задать его отдельно (`network.cpp:192–193`). Значение пика, отличное от30мВ, является явным расширением модели. Опубликованная дискретная программа с двумя полушагами напряжения не тождественна непрерывным уравнениям с RK4.

Для [Hodgkin–Huxley, 1952, с.518–520, уравнения и таблица3](https://materias.df.uba.ar/dnla2019c1/files/2019/03/hodgkin1952.pdf), после смены знака и начала отсчёта исходного напряжения `W=−(V+65)`:

```text
C dV/dt_ms = I − gNa m³h(V−ENa) − gK n⁴(V−EK) − gL(V−EL)
dq/dt_ms = αq(V)(1−q) − βq(V)q, q∈{m,h,n}
αm=.1(−V−40)/expm1((−V−40)/10); βm=4 exp(−(V+65)/18)
αh=.07 exp(−(V+65)/20); βh=1/(1+exp(−(V+35)/10))
αn=.01(−V−55)/expm1((−V−55)/10); βn=.125 exp(−(V+65)/80)
```

Это `model.cuh:90–105`. Напряжение — мВ, ток — мкА/см², проводимости — мСм/см², ёмкость — мкФ/см²; коэффициент1000 переводит производные в секунды. Скорости соответствуют6.3°C; температурного множителя в конфигураторе нет. Исходная статья задаёт Q10=3 для изменения температуры (с.519).

## Существенные ограничения

**P2, точность событий:** `network.cpp:333–349,404` интегрирует весь шаг и лишь затем выполняет сброс. При `V0=29.9` точный первый спайк происходит через0.000295308мс, а при шаге25мкс — на отметке0.025мс. В момент0.025мс native `u=−4.99006169`, эталон с своевременным сбросом `u=−5.00385307`. Ошибка не сводится к округлению записанного времени: изменяется последующая траектория. Для FS за200мс максимальная ошибка событий составляет0.863387/0.650887/0.203387мс при25/12.5/5мкс. Поэтому комментарий `model.cuh:138–140` о пределе `dt` следует понимать только как локальную задержку размещения события; общего такого предела относительно точного решения нет. Это численное ограничение, а не неверные уравнения.

**P3, начальное состояние HH:** `network.cpp:188–199` всегда задаёт `q0=αq(V0)/(αq(V0)+βq(V0))`. При `V0=−50мВ,I=0` это даёт0спайков. Мгновенный скачок от−65 до−50мВ с сохранением прежних затворов даёт1спайк и пик40.4148мВ по независимому решению. Начальные затворы не доступны в Config; такой опыт нельзя получить одним изменением V0. Существующая семантика корректна и описана; для voltage-shock/voltage-clamp опытов нужны отдельные поля `m0,h0,n0`.

**Область модели:** HH — фиксированная кинетика6.3°C без Q10. HH-порог служит детектором, не сбросом напряжения: для изолированного нейрона значения0/20/100мВ дают4/4/0событий за50мс при побитово одинаковых состояниях и пике40.2283мВ. В связанной сети изменение детектора меняет синаптические выбросы. Izh начальное напряжение и напряжение сброса, равные пику или выше него, отклоняются. Никакой гарантии точности для всех разрешённых экстремальных параметров из этих проверок не следует.

Ранее выполненные81 запуск ЛР1,14 DOP853-конфигураций и отдельная Radau-проверка учтены как существующие доказательства в `findings.json`; здесь они не запускались повторно. У коротких импульсов и жёстких экспоненциальных подсистем есть отдельный аудит в соседнем `../integration/`; он не дублируется здесь.


`build_probe.ps1` собирает только отдельный диагностический executable, связанный с уже существующей `network_core.lib`. Оригинальная CLI не пересобирается. `base.json` получен командой `network_studio_cli --preset 3 --save ...`. JSON-конфигурации, CSV, сообщения CLI — в `runs/`; эталоны — `reference.json`; точечные данные — `probe.csv`; полный результат — `findings.json` и `boundary_findings.json`; контрольные суммы — `manifest.json`. При повторе будут перезаписаны только материалы этого каталога. Для нового бинарного файла требуется явно пересмотреть фиксированный SHA и выводы проверки.
