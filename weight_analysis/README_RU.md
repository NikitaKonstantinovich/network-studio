# Анализ всех весов и сравнение снимков

Окно **«Веса всей сети…»** на основной панели работает со всеми синапсами,
включая связи, не выбранные для записи истории. Оно использует тот же
`SimulationRunner`; отдельный расчёт модели не запускается. Настройки окна не
вызывают `App::edit()` и не сбрасывают эксперимент.

## Работа в GUI

1. Откройте «Веса всей сети…». «Показывать текущий снимок» отображает последние
   согласованные данные вычислителя; рядом показаны модельное время и номер шага.
2. «Зафиксировать текущие веса» сохраняет неизменяемый снимок на безопасной границе
   завершённого шага. Расчёт может продолжаться. Название необязательно; по умолчанию
   оно содержит время. Новый снимок выбирается как цель сравнения.
3. «Добавить исходные веса» берёт **исходные веса Config**, а не реконструирует
   незаписанную историю. Для сравнения 0, 150 и 400 с зафиксируйте нужные состояния
   при достижении этих времён или загрузите сохранённые снимки/совместимые checkpoint.
   При работающем расчёте время подтверждённого снимка может быть позже нажатия кнопки.
4. «Загрузить снимок весов…» принимает `.nsweights`, совместимый `.nscp` или
   `PREFIX_summary.json` с `PREFIX_experiment.json` в том же каталоге. Загрузка
   добавляет снимок для анализа и **не заменяет текущий эксперимент**.
5. Выберите фильтры E/I, модели и включения, представление, число столбцов,
   допуск к границам обучения, базовый и сравниваемый снимки.
6. «Сохранить снимок весов…» сохраняет выбранный элемент списка. «Убрать снимок»
   удаляет его только из окна. «Экспорт распределений и чисел…» выгружает все числа.

Сохранённые снимки остаются при сбросе/замене сети и восстановлении checkpoint.
Проверка топологии выполняется заново. Окно перемещается, изменяет размер и может
быть вынесено на другой монитор штатным ImGui multi-viewport.

## Определения

- «Хранимый w (со знаком)» показывает непосредственно `plasticity[i].weight`;
  «Модуль |w|» показывает `abs(weight)`. Для проводимостного тормозного синапса
  хранимый вес положителен: окно не приписывает ему искусственный минус.
- Классификация E/I соответствует действующей модели: у Conductance STP порог
  `reversal <= -40 mV`; у токовых моделей — отрицательный исходный `Config.weight`
  без STDP. Текущий обученный вес не используется для переклассификации связи.
- Среднее и сумма относятся к выбранному представлению. Медиана чётной выборки —
  среднее двух центральных значений. Стандартное отклонение генеральное, делитель N.
  При N=0 статистики не определены (тире в GUI, `null` в JSON; сумма 0).
- Доля у нижней/верхней границы: `abs(raw_weight - bound) <= tolerance`.
  Допуск абсолютный, по умолчанию `1e-6`, единицы хранимого веса. Знаменатель —
  выбранные связи с настроенным `stdp=true`, включая временно замороженное обучение.
  При отсутствии таких связей доли не определены. При большом допуске одна связь
  может попасть в обе доли.
- Все распределения используют общий диапазон min/max объединённой выборки и
  одинаковые границы. Столбцы `[left,right)`, последний включает правую границу.
  Для одинаковых или машинно близких весов (когда столбцы иначе имели бы совпадающие
  границы double) добавляется запас `max(0.5, abs(min)*0.05)` с каждой стороны;
  пустая выборка использует диапазон 0–1 с нулевыми числами.
- Изменение — цель минус база. В режиме модуля это `|w₂| - |w₁|`, **не** `|w₂-w₁|`.
  В пару входят связи, прошедшие фильтры **в обоих** снимках. Таблица показывает
  исходные w, raw Δw и Δ выбранного представления. Сортировка — по убыванию
  модуля Δ представления, затем по структурной идентичности. GUI показывает первые
  100 строк, экспорт — все. «Точно без изменения» означает `raw_delta == 0`, без допуска.

## Идентичность и совместимость

У существующего графа нет постоянных UUID узлов/связей. Версия идентичности
`named-endpoints-model-astro-v1` использует уникальные имена нейронов с их моделью
и типом, пару источник/приёмник, модель синапса и имя прикреплённого астроцита.
Проверяется полный набор нейронов, астроцитов, химических связей и соединений
астроцитов. Перестановка массивов допустима; индексы используются только как подписи.
Параметры, координаты, стимулы и времена могут различаться.

Повторяющиеся имена, параллельные связи с одинаковой структурной идентичностью,
переименование или несовместимая топология **запрещают попарное сравнение**.
Индивидуальные распределения остаются доступны. Это консервативное структурное
сопоставление, а не доказательство общего происхождения произвольно пересозданных
сетей. Нельзя сопоставлять связи по одному номеру строки.

У старой сводки `final_synapse_weights` нет собственной карты идентичности и хэша
конфигурации. Импорт требует парный файл эксперимента по соглашению имён и проверяет
размеры, числа, границы и время. Убедитесь в происхождении пары: случайную подмену
парного файла старый формат надёжно обнаружить не позволяет. Это ограничение явно
отмечено в окне и поле `origin`. Несовместимые старые checkpoint этим путём не читаются.

## Файлы и CLI

`.nsweights` — отдельный JSON-документ `network_studio_weight_snapshot`, схема 1:
полная Config, все текущие веса, время, steps десятичной строкой, имя, происхождение
и версия идентичности. Double выводятся с 17 значащими цифрами для точного
восстановления; `uint64_t` не преобразуется через double. Запись атомарная через
существующий `write_atomic`. Размер файла ограничен 64 MiB, сеть — штатными лимитами,
окно — 16 сохранёнными снимками плюс текущий. Проверяются версия, размер массива,
конечность/допустимость весов, границы обучения, конфигурация и время.

Это **не checkpoint для продолжения**: здесь нет динамики ресурсов, следов STDP,
очереди и истории. На этапе анализа весов Config JSON 8, checkpoint 5 и fingerprint
численной сборки **не менялись** относительно непосредственно предыдущей сборки
истории на диске (`f5cd25fda1a20db68c7f3749637f08d96aed0adac9260b6e0ae3171cea13b085`).
Более старые несовместимые checkpoint по-прежнему требуют исходной сборки.

Команды из корня репозитория (пути вывода — вне `labs`):

```powershell
.\build\Release\network_studio_cli.exe --weights-initial .\examples\stdp_potentiation.json --output .\initial.nsweights
.\build\Release\network_studio_cli.exe --weights-from-checkpoint .\pause.nscp --output .\pause.nsweights
.\build\Release\network_studio_cli.exe --weights-from-summary ..\labs\lab6_1Hz_summary.json --output .\final_1Hz.nsweights
.\build\Release\network_studio_cli.exe --weights-analyze --snapshot .\initial.nsweights --snapshot .\pause.nsweights --output .\comparison --representation absolute --polarity E --model all --enabled all --bins 40 --tolerance 1e-6 --reference 0 --target 1
```

`--snapshot` повторяется до 17 раз. `--reference` и `--target` — индексы от 0 в этом
списке; по умолчанию 0 и 1 (0 при единственном снимке). Модели `all|stp|exp|tm`,
полярность `all|E|I`, включение `all|on|off`, представление `signed|absolute`.
При несовместимом сравнении CLI выгружает распределения и причину отказа, код выхода 2.

Экспорт создаёт `PREFIX_weights.csv` (все веса, признак выборки, идентичность,
метаданные связи), `_histograms.csv`, `_changes.csv`, `_delta_histogram.csv`,
`_statistics.json` (настройки, времена, происхождение, статистики и проверка совместимости).
Каждый файл заменяется атомарно; набор файлов целиком не является транзакцией.
Для отчёта используйте новый префикс. CSV UTF-8, разделитель запятая, дробный разделитель
точка, точность 17 цифр. Экспорт не подставляет конечные веса в прежнюю временную историю.

## Проверки и ограничения

```powershell
powershell -ExecutionPolicy Bypass -File .\build.ps1 -Test -Smoke
C:/Python313/python.exe -X utf8 .\weight_analysis\verify_labs.py
```

Второй сценарий читает сохранённые опыты 1/10 Гц, независимо пересчитывает статистики
в Python, проверяет гистограммы и точное отсутствие изменений I, сверяет старую
сводку и хэши входов. Создаёт новый каталог `verification/weight_snapshots_20261020/labs_*`.
**Он не выполняет новый 400-секундный эксперимент.** Результаты — в [отчёте](REPORT_RU.md).

Загрузка/экспорт выполняются синхронно и могут кратковременно задержать GUI;
численный поток независим. Live-распределение пересчитывается по опубликованным
снимкам (обычно 10 раз/с), а не на каждый численный шаг. Сохраняется только Config
и один вектор весов на снимок; вся History не копируется. Список окна не входит
в научную конфигурацию/checkpoint или workspace: нужные снимки сохраняйте отдельно.
