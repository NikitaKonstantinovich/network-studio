# Потоковая история на диске

Запись независима от модели, числа вычислительных потоков и частоты обновления GUI. Уравнения, адаптивный шаг, локализация событий, порядок суммирования и STDP не меняются. Один вычислитель синхронно передаёт записи архиву; при медленном диске расчёт ждёт, а не выбрасывает данные.

## GUI

1. Настройте сеть, длительность, шаг, частоту записи и выбранные объекты. Для опыта, превышающего прежний лимит истории, заранее включите **«Ограничить состояния в ОЗУ»**. Это политика хранения, а не прореживание отсчётов. Обычное изменение этой настройки сбрасывает эксперимент.
2. До первого шага откройте **«История на диске…»**. Введите путь **нового, ещё не существующего каталога**. Родительский каталог должен существовать. Кириллица поддерживается.
3. Выберите число сохраняемых в ОЗУ отсчётов и отдельно **«Записывать доставки по связям»**. Нажмите **«Включить запись до запуска»**. Запись остальных каналов обязательна. Принятые настройки приходят от вычислителя; начало записи не выполняет шага и не меняет состояние сети.
4. Запустите расчёт. В окне архива отдельно показаны диапазоны **экранного снимка**, **ОЗУ вычислителя** и **подтверждённых данных на диске**. Для состояний и событий границы ОЗУ могут отличаться. Масштаб отдельного графика — ещё один визуальный выбор, он не меняет доступность архива или интервал статистики.
5. Пауза, checkpoint и штатное закрытие подтверждают оставшийся буфер. **«Подтвердить буфер на диске»** доступно и во время работы: команда исполняется между завершёнными шагами.
6. Для анализа в новом процессе достаточно ввести путь существующего архива. Настройте профиль во встроенном окне **«Сеть / стимуляция»**, в окне архива задайте абсолютные **от — до** и нажмите **«Рассчитать по архиву»**. Анализ работает в отдельной фоновой задаче, не создаёт Simulator и не изменяет текущий опыт. Показаны покрытие, недостаточная предыстория, статус архива и исключённый неподтверждённый хвост. Экспорт сохраняет фактический профиль и интервал обработанного результата, даже если после запуска анализа поля были изменены.

Сброс/загрузка другой сети подтверждает старую запись и закрывает её. Для нового опыта нужен новый каталог и новое явное включение. Изменение параметров записи или модели обычным редактором по-прежнему сбрасывает опыт. Сам каталог не сохраняется в научном JSON: случайное открытие конфигурации не перезаписывает прежние результаты.

## CLI

Из корня проекта, создав родительский каталог `verification/my_archive`:

```powershell
.\build\Release\network_studio_cli.exe --config experiment.json --archive verification/my_archive/run --archive-rows 10000 --archive-deliveries yes --stop-at 150 --checkpoint verification/my_archive/pause.nscp --output verification/my_archive/ram150

# Новый процесс. Сначала прикрепляется архив, затем допустимы команды протокола/продление.
.\build\Release\network_studio_cli.exe --resume verification/my_archive/pause.nscp --archive-append verification/my_archive/run --archive-deliveries yes --until 400 --checkpoint verification/my_archive/final.nscp --output verification/my_archive/ram400

# Ветвь из прежней точки, когда исходная запись уже ушла дальше.
.\build\Release\network_studio_cli.exe --resume verification/my_archive/pause.nscp --archive verification/my_archive/branch --archive-deliveries yes --until 400 --output verification/my_archive/branch_ram

.\build\Release\network_studio_cli.exe --inspect-archive verification/my_archive/run
.\build\Release\network_studio_cli.exe --analyze-archive verification/my_archive/run --analysis-profile experiments/analysis_profiles_20261020/lab6_profile.json --analysis-from 280 --analysis-to 400 --output verification/my_archive/stat280_400
.\build\Release\network_studio_cli.exe --export-archive verification/my_archive/run --analysis-from 280 --analysis-to 400 --output verification/my_archive/raw280_400
```

Это примеры команд, **не заявление о проведённом 400-секундном опыте**. Профиль нужно проверить на соответствие загруженной сети и источнику. `--archive-rows` по умолчанию 10000; `--archive-deliveries` — `no`. При продолжении режим доставок должен совпадать с исходным. Число строк ОЗУ берётся из checkpoint. До первого запуска включение архива устанавливает ограниченные журналы ёмкостью 50000 событий на канал; выбранная частота отсчётов не меняется.

Время `--until`, `--stop-at` и границы анализа — абсолютные секунды от модельного нуля; `--run-for` — длительность продолжения. `--stop-at` останавливает на первой завершённой границе основного шага не раньше запроса. Запись архива сама новых границ интегрирования не добавляет.

Обычный `--output` экспортирует оставшуюся историю **ОЗУ**, а не весь архив. В summary добавлены `state_history_from_s`, `state_sample_begin`, `rolling_state_history`. Полные дисковые каналы экспортируются отдельной командой `--export-archive`, потоково и только в новый префикс вне архива. Интервал экспорта `[from,to)`; для включения конечного отсчёта задайте `to` больше конечного времени. Выход: состояния/веса с индексами столбцов, спайки/астроцитарные выбросы, доставки, индивидуальные стимулы, обновления общих импульсов, протоколы и файл покрытия `_archive.txt`. Отсутствие завершающего `_archive.txt` означает незавершённый экспорт. Нулевые индексы столбцов соответствуют `network.h`, их модели и параметры находятся в `config.json`.

## Формат и память

Каталог формата **NSH 2** содержит перечисленные ниже файлы. Новый читатель
поддерживает NSH 1 и 2; старый читатель не следует использовать для NSH 2.

- `config.json` — начальная полная научная конфигурация: граф, модели, начальные веса, параметры, seed/шум, входы и выбор записываемых столбцов.
- `manifest.nsh` — атомарно заменяемый двоичный манифест с типом документа, версией, fingerprint сборки, ID архива, происхождением ветви, диапазоном подтверждённого времени, числом шагов/блоков/записей, режимом доставок, статусом и контрольной суммой конфигурации.
- `0000000000000001.nshb`, … — неизменяемые блоки; собственные тип/версия, ID архива, порядковый номер, число записей и контрольная сумма.
- `writer.lock` — эксклюзивная Win32-блокировка открытым дескриптором; после аварии ОС освобождает дескриптор. Сам файл удалять не требуется.

Числа `double` записываются как биты IEEE-754 binary64, счётчики — `uint64_t`, little endian. FNV-1a-64 обнаруживает случайное повреждение, **не является криптографической подписью**. Не сериализуются указатели и дампы объектов.

Каждая запись имеет тип и длину. Каналы: выбранные состояния и текущие веса; все спайки и выбросы астроцитов; опционально доставки; индивидуальные начала импульсов; начало/окончание общего импульса с устойчивым `(stimulator,pulse)` и получателями; снимки конфигурации/протоколов/команд при изменениях. Окончание общего импульса — отдельное обновление, а не второй стимул. Индивидуальные окончания определяются таблицей интервалов и журналом смен протокола; семантика `[start,stop)` сохраняется. Шум воспроизводится из сохранённых seed, параметров и времени; дополнительного потребления модельного генератора нет.

NSH 2 добавляет типы 7/8 — полную строку [нейроанимата](../neuroanimat/README_RU.md)
и версию его среды. У версии есть устойчивый номер и признак `context`:
контекст среды в начале архивной ветви не является новым изменением.
Строки траектории и среды входят в потоковый экспорт архива; порядок при
одинаковом времени сохраняется. Перенос среды в контекст не дублирует движение.

Ограничение памяти истории сети не распространяется на полную траекторию
нейроанимата: она пока остаётся в ОЗУ (до 1 млн строк), независимо от
экранного хвоста 20 000 строк и записи на диск. GUI-анализ робота использует
Simulator/checkpoint; отдельного потокового GUI-анализа траектории только
из архива пока нет. Потоковый сетевой анализ по спайкам продолжает работать.

Рабочий буфер — **4 МиБ**. Одна крупная запись метаданных допускается до **64 МиБ**; превышение вызывает ошибку. Проверка размеров выполняется до крупных выделений читателем. Текстовые метаданные и проверка блока требуют временных копий, поэтому 4 МиБ — не предел RSS всего приложения. История состояний в ОЗУ хранит не более `history_capacity` строк, освобождая старую половину при заполнении; прежний бюджет 32 млн чисел остаётся. Журналы, активные импульсы, текущая очередь доставок и протоколы имеют свои прежние явные ограничения. Достижение предела протоколов/очереди не скрывается архивом.

Сетевой анализ использует **один общий алгоритм** для памяти и диска. Архив читается по блокам с проверкой сумм. Отобранные спайки до правой границы последовательно помещаются во временный дисковый файл, затем читаются восьмью страницами по 2048 записей. Кандидаты пачек из далёкой предыстории не накапливаются. Результат ограничен 200000 бинов и 2 млн пачек/стимулов; слишком большой запрос явно отклоняется. Временный файл требует свободного места в системном TEMP и удаляется после анализа. После аварии процесса может остаться `network-analysis-*.tmp`; это вспомогательный файл, не часть архива. Время чтения пропорционально подтверждённому префиксу; случайного индекса по времени в версии 1 нет.

Предыстория детектора не обрезается до фиксированного окна: гистерезис и объединение могут зависеть от более ранних спайков. Сохраняются [прежние правила анализа](../experiments/ANALYSIS_PROFILES_RU.md): владение пачкой по началу в `[from,to)`, явная определённость детектора, исключение неполных окон ответа, сравнение только одинаковых профилей и покрытий.

## Порядок, подтверждение и ошибки

Физический порядок событий не изменён: локализация порогов на общей траектории, сброс Ижикевича (без сброса HH), доставки/ресурсные скачки, астроцитарные выбросы, STDP по прежним следам, новые следы, продолжение потока. Журнал фиксирует доставки в порядке `(t_arrival,synapse,t_emit)`, затем спайки в порядке индексов нейронов, затем астроцитов; отсчёт на той же границе записывается после скачков. Смена входа и его импульсы регистрируются в прежнем порядке контроллера. Для одинакового времени окончательный порядок архива задаётся **номером блока и порядком записи внутри блока**; сортировка только по времени не нужна и может разрушить порядок обновлений протокола. Генерация спайка и доставка — разные типы записи.

Буфер может физически сбрасываться внутри шага, но новые блоки становятся доступными читателю **только после атомарного обновления манифеста между полностью завершёнными `step()`**. Подтверждение происходит при заполнении блока, каждые 4096 основных шагов, при завершении, паузе, checkpoint и штатном закрытии. Промежуточная группа событий никогда не объявляется подтверждённой.

После аварийного завершения читатель использует только перечисленный счётчиком манифеста префикс. Неполный/лишний последний блок и временный файл отображаются как **неподтверждённый хвост**, не учитываются в анализе и не удаляются. Повреждение блока **внутри подтверждённого префикса** — ошибка, а не молчаливое сокращение интервала. Для хвоста разрешён анализ целого префикса и новая ветвь из checkpoint; автоматического усечения исходных файлов или продвижения манифеста нет.

Любая ошибка записи останавливает приём данных и доводится до CLI/GUI. Запись не переключается незаметно в режим «только ОЗУ». Старый подтверждённый манифест остаётся; новые блоки не выдаются за полный опыт. `status=complete` означает достижение конечного времени; `open` — незавершённую запись (включая паузу или аварийно остановленный процесс). Метод атомарной замены использует штатную Windows-операцию с write-through; защита от произвольного сбоя носителя/питания и физической порчи всех копий не обещается.

## Checkpoint и ветви

При включённом архиве checkpoint хранит полное **динамическое состояние** и оставшееся окно истории ОЗУ, а полный журнал находится в каталоге архива. Копировать один `.nscp` недостаточно для переноса всей истории; сохраняйте каталоги архивов и родителей. Архив подключается до первого шага исходного опыта или при восстановлении точки, уже связанной с архивом.

Перед сохранением checkpoint подтверждается архив. Контрольная точка содержит устойчивую привязку к каталогу/ID, номеру последнего блока, числу записей, времени/шагам и подписи сохранённого состояния/протокола. При загрузке файл архива не открывается автоматически. Продолжение вычисления до явного выбора архива отклоняется.

**Продолжить прежний архив:** допустимо только при полном совпадении привязки и текущего состояния с последним подтверждённым концом. Старый checkpoint, чужой каталог, изменённый протокол до подключения, другой режим доставок, конкурентный писатель или неподтверждённый хвост дают ошибку. Старые блоки не перезаписываются, прежние записи не добавляются повторно.

**Новая ветвь:** новый каталог с отдельным ID, исходным временем checkpoint и происхождением. В нём записывается только продолжение от этой точки; старые события не копируются. Активный общий импульс переносится как контекст, не новый импульс. Родительский архив не изменяется. Анализ и потоковый экспорт читают родительский префикс **только до сохранённой границы checkpoint**, затем продолжение ветви. Более позднее развитие родителя не попадает в ветвь. Контекстный отсчёт и открытый импульс не дублируются. Поддержано до 16 звеньев; цикл, отсутствующий или повреждённый родитель дают явную ошибку. Происхождение — ссылка, а не резервная копия: сохраняйте каталоги родителей по исходным абсолютным локальным путям. Сетевые UNC-ссылки автоматически не открываются. В экспортном описании указано покрытие доставок каждого звена, если их режим записи различался.

Несколько независимых ветвей и повторов запускает [пакет эксперимента](../experiment_package/README_RU.md). При его проверке исправлено последовательное чтение пути и ID родителя: длинные UTF-8 пути больше не попадают под 128-байтовый лимит ID из-за неопределённого порядка вычисления операндов `operator+`. Формат архива не изменился; строгий fingerprint NSCP изменился и приведён в документации пакета.

Научный JSON — **9** (чтение 1–8 сохранено; `history_capacity=0` означает полную историю состояний в ОЗУ). Checkpoint — **7**: кроме смещений обрезанной истории, привязки архива и состояния нейроанимата, сохраняются счётчики интегрирования. **Checkpoint 1–6 и несовпадающие fingerprint несовместимы с этой сборкой.** Обход проверки не добавлен; старые точки продолжайте прежним EXE. Workspace остаётся **5**, профили не меняются. Исторический [отчёт дисковой истории](REPORT_RU.md) относится к JSON 8 / checkpoint 5 / NSH 1; проверки NSH 2 описаны в [отчёте нейроанимата](../neuroanimat/REPORT_RU.md), а текущая диагностика — в [описании шага интегрирования](../performance/20261020_step_range/README_RU.md).

Сценарии проверок: `archive_tests.cpp`, `process_test.cmake`, `native_test.cmake`. Измерения: `python disk_history/measure.py` (последовательные отдельные процессы, три повтора для 0,5 и 10 модельных секунд). Штатная сборка и проверки: `powershell -ExecutionPolicy Bypass -File .\build.ps1 -Test -Smoke`. Результаты этого этапа — в отдельном `verification/disk_history_20261020/`; лабораторные входы не изменяются.

Метод интегрирования (`integration_method`) сохраняется в `config.json`
архива и версиях протокола; их контрольные суммы проверяются читателем.
Схема NSH 2 не менялась. Текущий JSON 10 читает предыдущие схемы; отсутствие
поля в старом JSON означает адаптивный RK4. Продолжение требует NSCP 8 и
точного fingerprint сборки, без замены метода при восстановлении.
