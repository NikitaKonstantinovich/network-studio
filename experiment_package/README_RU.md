# Воспроизводимый пакет и ветви из общего состояния

Пакет схемы **1** — каталог с `manifest.json`, неизменяемыми входами и копией
конкретного `network_studio_cli.exe`. `runtime/package.py` запускается Python
**3.10+**, без сторонних библиотек. GUI, уравнения, допуски, порядок суммирования,
шум и обработка событий используются прежние. Это сценарный инструмент поверх
существующего CLI, а не ещё один решатель.

## Быстрый старт

Из `E:/asp/26_27/configurator`, каждый раз укажите **новый** каталог:

```powershell
# Короткая синтетическая проверка: фон 0–0,2 с, ветви до 1,4 с,
# два seed × три протокола × два независимых повтора.
powershell -ExecutionPolicy Bypass -File .\experiment_package\prepare.ps1 `
  -Scenario Short -Seeds '42,43' -Python C:/Python313/python.exe `
  -Destination E:/asp/26_27/configurator/verification/my_short_package -Run

# Только подготовить и проверить лабораторный пакет — без расчёта.
powershell -ExecutionPolicy Bypass -File .\experiment_package\prepare.ps1 `
  -Scenario Laboratory -Seeds '42' -Python C:/Python313/python.exe `
  -Destination E:/asp/26_27/configurator/verification/my_lab400_package

# Отдельная команда полного опыта; длительный запуск выполняется ТОЛЬКО здесь.
C:/Python313/python.exe -X utf8 `
  E:/asp/26_27/configurator/verification/my_lab400_package/package/runtime/package.py run `
  --package E:/asp/26_27/configurator/verification/my_lab400_package/package `
  --output E:/asp/26_27/configurator/verification/my_lab400_package/results
```

Лабораторный генератор сценария читает `labs/lab6_1Hz_experiment.json` и существующий
профиль `experiments/analysis_profiles_20261020/lab6_profile.json`. Проверяет ожидаемые
размеры сети и фазу, сохраняет научную Config без изменения. В ней 500 нейронов,
15 041 связь, seed генерации/шума 42, получатели с **нулевыми** индексами
207, 262, 263, 336, 354, 496. Команды на **150 с** отключают источник либо задают
1/10 Гц. Первая подача — **150,05 с**, амплитуда 25, ширина 3 мс, окончание 400 с.
Сравнение статистики: **[280,400)**. Ни один файл `labs` не изменяется.
Сценарий не загружает старые несовместимые checkpoint и не утверждает совпадение
с прежним опытом NeuroNet. Короткий пример — отдельная синтетическая сеть.

При одном seed и двух повторах полного сценария вычисляются один фон 150 с и
шесть продолжений по 250 с — **1650 модельных секунд суммарной работы**.
Это не оценка настенного времени. `-Seeds '42,43'` создаёт два отдельных фоновых
опыта и увеличивает объём работы вдвое.

## Собственный сценарий

`make_scenario.py` создаёт наглядный `spec.json`; его можно отредактировать **до**
создания пакета. Все времена абсолютные, в секундах от начала опыта, а не
длительности ветви. `until_s` должен совпадать с `Config.duration`, фоновая граница
— точно с `N * dt`. Скрипт не округляет команды и не переносит первый импульс.

Основные поля спецификации:

- `document_type: network_studio_experiment_spec`, `schema_version: 1`, `name`;
- `config`: исходная JSON; `checkpoint`: необязательный самостоятельный NSCP,
  уже находящийся точно на `background_until_s`;
- `background_until_s`, `until_s`; `analysis_profile`,
  `analysis_interval: {from_s, to_s}`;
- `experiments: [{id, noise_seed}, ...]`, `repeats`,
  `branches: [{id, commands}, ...]`;
- `threads`: `1/2/4/6/8/12/16/auto`;
- `storage: {mode: archive|memory, rows: 128, deliveries: false}`;
- `tolerances`: `spike_time_s`, `stimulus_time_s`, `weight_absolute`,
  `weight_relative`, все неотрицательные и конечные.

Пути спецификации относительны её каталогу. Имена ветвей/опытов — ASCII ID,
регистронезависимо уникальны; сами пути могут содержать кириллицу и пробелы.

```powershell
python -X utf8 experiment_package/package.py create --spec scenario/spec.json `
  --destination new_package --cli build/Release/network_studio_cli.exe
python -X utf8 new_package/runtime/package.py validate --package new_package --output new_results
python -X utf8 new_package/runtime/package.py run --package new_package --output new_results
```

`create` копирует исходники документов, профиль, необязательный NSCP, CLI и runner;
SHA-256 и размеры всех файлов записывает в манифест. Даты, ОС, архитектура,
процессор, версия Python, идентификатор численного ядра и алгоритма также сохранены.
Config нормализуется существующим C++ JSON API. Допустимые изменения производных
Config — **только явно указанный seed шума и политика хранения**. Для archive это
`history_capacity=rows`, `bounded_journals=true`, `journal_capacity=50000`;
выбранные состояния, dt, sample, модель и остальные параметры не меняются.
Исходная Config хранится отдельно без изменения байтов.

Все метаданные генерации, включая её seed, берутся из `Config.generation`.
Пустая метаинформация не заменяется выдуманным seed: уже сохранённый граф остаётся
воспроизводимым входом, но его генерацию нельзя восстановить по неизвестному seed.
Серия `noise_seed` использует **фиксированный граф**. Другой seed генератора требует
отдельно сгенерированной Config и нового пакета — скрытой перегенерации нет.

## Протокол и независимость ветвей

Принимается существующий документ `network-studio-stimulator-commands`, schema 1.
Можно использовать `commands` либо журнал уже принятых `changes`: они объединяются
по `(time, sequence)`; исходный журнал сохраняется отдельно. У принятой пространственной
команды фиксируются **записанные получатели**, без повторного выбора по геометрии.
Новые пространственные команды без записанного принятия необходимо сначала
преобразовать в явный список. Латчи не используются как команды.

`time` — уже принятое время, `value.signal.start + first_delay` задаёт фазу;
`restart` означает явно записанный перезапуск. Replay не повторяет GUI-процедуру
согласования частоты. Необходимо записать фактически принятую границу, а не только
время первоначального запроса. Сохраняются интервалы **[start,stop)** и существующий
порядок событий/сбросов/обучения. При одном времени порядок команд задаёт `sequence`.
Запись событий сохраняет нулевые индексы и отличает спайки, выбросы, индивидуальные
стимулы и общие импульсы. Доставка не становится спайком.

Для каждого seed фон считается один раз. Каждый повтор каждой ветви — **новый
процесс**, который загружает один и тот же неизменённый `background.nscp` и создаёт
отдельный архив-продолжение. Завершённая ветвь никогда не становится началом следующей.
Общий checkpoint проверяется SHA-256 перед каждым запуском; его происхождение,
конфигурация и время фиксируются в `common/provenance.json`.

Отключение общего источника не выключает индивидуальные входы, постоянный ток,
шум или обучение. В поставленных примерах индивидуальные импульсы отключены
явно. Никакого дополнительного сброса состояния или следов STDP нет.

## Предварительная проверка и отчёт

`validate` не выполняет шагов. Проверяет SHA/наличие файлов, безопасные относительные
пути, версию, конкретный CLI, Config и NSCP **штатным строгим загрузчиком**, seed,
получателей и значения команд, порядок/уникальность/времена, профиль, интервалы,
предел числа bins, отсутствие активного автоматического этапа и скрытых ожидающих
команд. Существующий выходной каталог запрещён. Пределы: 1000 запусков, 100 seed,
100 повторов, 32 ветви; штатные ограничения Config, checkpoint и архивов остаются.

Будущие данные до выполнения не объявляются доступными: preflight показывает
`available_now_until_s` и отдельно планируемый интервал. После **каждой** ветви
анализ повторно требует `full_interval` и `prehistory_complete` существующего
анализатора. Применяются прежние правила предыстории детектора, принадлежности
пачки по началу и исключения стимулов с неполным окном ответа. Настройки и интервал
включены в каждый результат; одинаковый масштаб графика не служит критерием.

`REPORT.md` и машиночитаемый `report.json` содержат:

- происхождение/seed/threads (запрошенные и фактические), длительность каждого
  расчёта, фактическое конечное время и SHA выходов;
- проверку принятых команд, их времён и реальных получателей;
- журналы `spike.jsonl`, `release.jsonl`, `stimulus.jsonl`, `pulse.jsonl`, числа и
  времена первых/последних общих импульсов; это фактические данные решателя;
- сравнение спайков и стимулов по порядку, идентичности, числу и времени;
- все конечные веса из штатной сводки; перед попарным сравнением проверяется
  полная идентичность исходной топологии, иначе разность запрещена;
- точное совпадение отдельно от допуска: для времени абсолютный допуск, для веса
  `abs(a-b) <= atol + rtol * max(abs(a),abs(b))`; пропавшее событие или другая
  идентичность не проходят за счёт допуска;
- значения каждого запуска и mean/median/min/max/выборочное SD по seed. Повторы
  одного seed не увеличивают статистическое N; N=1 имеет SD=null.

Повторы одинаковых условий **обязаны совпасть точно**, допуски этого требования
не ослабляют. `comparison.nscp` создаётся после строгой загрузки финального NSCP
и удаления только адреса/ID архива; остальные байты — Config, полный state,
адаптивный шаг, пороги, очередь, ресурсы, веса/следы, история, счётчики и протокол —
участвуют в сравнении. Это файл для сравнения, не новый научный источник полного
архива. Полные события продолжения читаются потоково с диска и сравниваются отдельно;
вся длительная история состояний в память не загружается.

## Ограничения и совместимость

- Пакет схемы 1 описывает протоколы обычных стимуляторов. Он не подменяет
  протокол действий нейроанимата. Для ветвей, этапов и воспроизведения движения
  используйте штатный CLI с `--animat-commands` либо
  [neuroanimat/run_demo.py](../neuroanimat/run_demo.py);
  [инструкция и границы поддержки](../neuroanimat/README_RU.md).
- Импорт schema 1 поддерживает самостоятельный NSCP с полной сохранённой историей,
  без ссылки на внешний архив, и только **без изменения seed**. Config должна точно
  соответствовать сохранённой Config с исходными весами. Для архивного полного
  опыта запускайте пакет из Config: он сам создаст общий архив и дочерние ветви.
  Импорт внешней цепочки архивов и её перенос пока не реализован; отказ явный.
- Входной пакет можно перемещать. Созданные **результаты** с архивами сохраняйте
  по исходным абсолютным путям: это ограничение существующей ссылки на родителя.
  Для нового размещения повторно запустите входной пакет в новом каталоге.
- Ошибка/прерывание оставляет `status=failed` (либо последний `running` при убийстве
  процесса), логи и уже подтверждённые архивные блоки. Каталоги не перезаписываются;
  автоматического продолжения частично выполненного пакета нет. Финальный отчёт
  `complete` появляется только после всех запусков и сравнений.
- Для анализа в режиме memory запрещено усечение журналов. Для долгих опытов
  используйте archive; записи доставок включаются отдельно и могут быть велики.
- Точное совпадение проверено в одной сборке и окружении; сравнение аппаратного
  параллелизма при preflight не является полной проверкой идентичности CPU/FP среды.
  Идентификатор ядра, CLI SHA и фактическое окружение сохранены, fast-math не включён.
- Исправлено последовательное чтение пути/ID в существующем архиве: прежнее
  выражение зависело от порядка вычисления операндов C++ и ломалось на длинных
  UTF-8 путях. На том историческом этапе численная семантика не менялась,
  NSCP оставался схемы 5, а строгий fingerprint стал
  `f274197dad3d5b220f780e53e596cd50b989cb3ef155827de4c1b3f2178f1be6`.
  Старые NSCP с `f5cd25fd…` открывайте старой сборкой, сохранённой в
  `verification/experiment_package_20261020/previous-build/`. Проверка совместимости
  не отключалась, конвертация несовместимых checkpoint не выполнялась.
- Текущая сборка с нейроаниматом использует **Config JSON 9 / NSCP 7 / NSH 2**.
  Пакет по-прежнему фиксирует конкретный CLI и его fingerprint; старый пакет
  запускается своей сохранённой сборкой. Подмена EXE новым несовместимым
  решателем не разрешена. Текущие SHA-256 и fingerprint находятся в
  [отчёте о шаге интегрирования](../performance/20261020_step_range/REPORT_RU.md).

Проверки и фактические длительности: [REPORT_RU.md](REPORT_RU.md).
